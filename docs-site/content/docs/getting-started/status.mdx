The [public-testnet readiness assessment](https://github.com/Anastasia-Labs/midgard/blob/main/docs/public_testnet_readiness.md)
owns Midgard's release decision and acceptance checklist. Its last full review
was 2026-09-01, consolidated on 2026-09-07, and the recorded decision is
**no-go for an open public testnet**. Documentation consolidation does not rerun
acceptance or close a release gate.

The honest-path pipeline and watcher source catalogue exist. Source installation,
unit tests, and local emulator success do not establish public readiness.
A release needs evidence tied to its revision, deployment identity, configuration,
and environment, with known limitations recorded.

## Which evidence to use

- [Readiness assessment](https://github.com/Anastasia-Labs/midgard/blob/main/docs/public_testnet_readiness.md):
  public claim, deployment provenance, operations, recovery, economics, user
  lifecycles, and release acceptance.
- [Catalogue status](https://github.com/Anastasia-Labs/midgard/blob/main/docs/fault-proofs/catalogue-status.md):
  installed proof categories and their deployment boundaries.
- [Coverage matrix](https://github.com/Anastasia-Labs/midgard/blob/main/docs/fault-proofs/coverage-matrix.md):
  proof obligations and supported evidence paths.
- [Testing status](https://github.com/Anastasia-Labs/midgard/blob/main/docs/fault-proofs/testing-status.md):
  validation commands, retained evidence, and acceptance limitations.

Use those maintained records before making a deployment or public security
claim. A successful node readiness response, one completed transaction, or one
proof-family demonstration proves only the behavior exercised by that check.
