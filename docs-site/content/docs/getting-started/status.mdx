This page summarizes the repository's own **Public Testnet Readiness Checklist**
(`public_testnet_readiness.md`, last reviewed 2026-07-02). That checklist reviews
the repository state for an *externally reachable public testnet* and
treats Midgard as a production-grade L2, so its bar includes adversarial safety,
deterministic deployment identity, restart/recovery behavior, public client
ergonomics, monitoring, and runbooks. It is deliberately stricter than "the local
happy path works."

<Callout type="warn" title="Verdict: no-go for an open public testnet">
As of the 2026-07-02 review, the decision is **no-go for an open public testnet.** The core happy-path
L2 pipeline is materially implemented, but public readiness blockers remain:
public fraud-proof / data-availability completion, deterministic deployment
fingerprinting, ingress and ops hardening, full public acceptance gates,
restart/recovery acceptance, and withdrawal/payout surface hardening. Public
messaging must not claim full fraud-proof readiness until the proof families and
proof-bundle / data-availability surfaces are complete.
</Callout>

## What already works

The checklist confirms the core happy-path L2 pipeline is materially implemented:
node startup, schema migrations, protocol initialization, operator
registration/activation, `/submit`, admission/validation, mempool processing,
deposit projection, block commitment, confirmation, merge, reserve/payout
builders, and SDK/provider primitives.

## Headline launch blockers

The checklist enumerates the blockers that keep the decision at no-go. In brief:

- **Deployment fingerprint**: every node must store and verify a full deployment
  identity (network id, one-shot out-ref, script hashes, reference-script
  out-refs, fraud-proof catalogue root, compiler and blueprint hashes, protocol
  parameter hash, era/version) and fail closed on a mismatch.
- **Public fraud-proof / proof-DA milestone**: at least the intended public
  fraud-proof family must run end-to-end on preprod, with persisted proof bundles
  and public endpoints an external watcher can use without privileged DB access.
- **Ingress and ops hardening**: TLS, rate limiting, private admin endpoints, and
  a mandatory `ADMIN_API_KEY` in public profiles.
- **L1 finality / rollback / provider-consistency policy**: protocol-affecting L1
  observations must not finalize from first provider visibility alone.
- **Key custody and admin authority model**: separated key ownership, rotation,
  and attributable, replay-protected admin identities.
- **Operator liveness, Sybil, and incentives**: either permissionless operation
  with slashing/inactivity enforcement, or an explicitly declared curated model.
- **A clean public-testnet acceptance gate** and **CI aligned to it**.
- **Removing placeholder economics / demo parameters** from public-testnet config.
- **Public release, support, and data-retention posture** (SBOMs, `SECURITY.md`,
  status surfaces, retention policy).

For the full evidence index, implementation waves, and per-area acceptance
criteria, see `public_testnet_readiness.md` in the repository root.
