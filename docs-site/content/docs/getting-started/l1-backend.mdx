title: "L1 Backend"
description: "Bring up the Cardano L1 stack Midgard depends on: a node bootstrapped from Mithril, with Ogmios and Kupo, from the node package's compose overlay."
---

Midgard needs a synced Cardano Layer 1 backend to read chain state and submit
transactions. The canonical L1 stack lives in `demo/midgard-node` as the
`docker-compose.kupmios.yaml` overlay on `docker-compose.yaml`. It boots a
Cardano node from a certified Mithril snapshot rather than syncing from genesis,
restores an official Kupo snapshot, and starts Ogmios and Kupo with healthchecks
the node waits on. Every Midgard role (node, DA committee, watcher) uses this
stack; a host that runs no node starts only the L1 services from it.

## Services

| Service               | Image                                                      | Role                                                                                                                                                                                  |
| --------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mithril-bootstrap`   | `ghcr.io/intersectmbo/mithril-client` (digest-pinned)      | One-shot: validates `NETWORK` against the Mithril endpoints and `CARDANO_NODE_IMAGE_TAG` against the certified snapshot, then restores the Cardano DB into `./cardano/db` when empty. |
| `kupo-bootstrap`      | same image                                                 | One-shot: restores the official Kupo SQLite snapshot into `./cardano/kupo` when empty and verifies its MD5.                                                                           |
| `cardano-node`        | `ghcr.io/intersectmbo/cardano-node:11.1.0` (digest-pinned) | Runs the Cardano node. Exposes its Unix socket under `./cardano/ipc`; healthy once `/ipc/node.socket` exists.                                                                         |
| `cardano-node-ogmios` | `cardanosolutions/ogmios:v7.0.0` (digest-pinned)           | WebSocket/HTTP bridge to the node, started with `--include-transaction-cbor`. Listens on `1337`; healthy via `ogmios health-check`.                                                   |
| `kupo`                | `cardanosolutions/kupo:v2.11.0` (digest-pinned)            | Chain indexer over Ogmios with `--match "*" --since origin`, **no** `--prune-utxo`. Listens on `1442`; healthy only once `/health` returns `200`.                                     |

<Callout type="warn" title="Kupo must not prune">
  The node's forced-order carriage reader reads spent carriage outputs, which a
  pruning index deletes. The official Kupo snapshot the bootstrap restores was
  itself built pruned, so outputs spent before its snapshot point are absent.
  That is harmless for a deployment you initialise after bring-up. To join a
  deployment whose L1 history predates the snapshot, set
  `KUPO_BOOTSTRAP_MODE=origin` before the first start so Kupo syncs from origin
  instead. Kupo `v2.10.0` or newer is required for the `?resolve_hashes` query
  the same reader uses.
</Callout>

## Environment variables

Configuration comes from `demo/midgard-node/.env`, copied from `.env.example`.
`NETWORK` is the source of truth; the Mithril defaults are derived from it and
any explicit override must match it or the bootstrap refuses to start.

| Variable                                                              | Default                                                                       | Purpose                                                                                             |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `NETWORK`                                                             | `Preprod`                                                                     | `Mainnet`, `Preprod`, or `Preview`; drives node config, Mithril network, Kupo snapshot.             |
| `CARDANO_NODE_IMAGE_TAG`, `CARDANO_NODE_IMAGE_DIGEST`                 | `11.1.0`, `sha256:7b36...`                                                    | Node image. The tag stays a bare version because the bootstrap compares it to the snapshot.         |
| `OGMIOS_IMAGE_TAG`, `KUPO_IMAGE_TAG`, `MITHRIL_CLIENT_IMAGE_TAG`      | `v7.0.0@sha256:...`, `v2.11.0@sha256:...`, `2630.1-hotfix-3f6cb73@sha256:...` | Image pins. `.env` values override the compose defaults; change tag and digest together.            |
| `MITHRIL_AGGREGATOR_ENDPOINT`, `MITHRIL_*_VERIFICATION_KEY_URL`       | derived from `NETWORK`                                                        | Explicit overrides are cross-checked against `NETWORK`.                                             |
| `MITHRIL_SNAPSHOT_DIGEST`                                             | `latest`                                                                      | Certified snapshot to restore.                                                                      |
| `KUPO_BOOTSTRAP_MODE`                                                 | `snapshot`                                                                    | `snapshot` restores the pruned official snapshot; `origin` syncs Kupo from origin (complete, slow). |
| `KUPO_SNAPSHOT_RELEASE_TAG`, `KUPO_SNAPSHOT_URL`, `KUPO_SNAPSHOT_MD5` | `v2.8`, empty, preprod MD5                                                    | Official Kupo snapshot source. Clear `KUPO_SNAPSHOT_MD5` when `NETWORK` is not Preprod.             |
| `OGMIOS_PORT`, `KUPO_PORT`                                            | `1337`, `1442`                                                                | Host port mappings.                                                                                 |

## Bringing it up

Before starting, have a [checkout of the repository](/docs/getting-started/local-dev)
and Docker with the Compose v2 plugin. Plan for tens of gigabytes of disk under
`demo/midgard-node/cardano` and expect the first start to spend a while
downloading; later starts skip both bootstraps when data is already present. A
socket or reachable indexer does not prove synchronization; verify that node
and indexers have caught up before initializing Midgard.

<Steps>

<Step>
Copy the example environment and set `NETWORK`:

```sh
cd demo/midgard-node
cp .env.example .env
```

</Step>

<Step>
Start only the L1 services. The bootstraps run to completion first, then the
long-running services start in dependency order:

```sh
docker compose -f docker-compose.yaml -f docker-compose.kupmios.yaml \
  up -d cardano-node-ogmios kupo
```

</Step>

<Step>
Wait for `kupo` and `cardano-node-ogmios` to report healthy, then confirm the
route the node will use:

```sh
docker compose -f docker-compose.yaml -f docker-compose.kupmios.yaml ps
node dist/index.js l1-provider-preflight --json
```

Ogmios is reachable on `127.0.0.1:1337` and Kupo on `127.0.0.1:1442` from the
host; inside the compose network they are `cardano-node-ogmios:1337` and
`kupo:1442`, which the overlay injects into the node and migration containers.

</Step>

</Steps>

Changing networks requires clearing `./cardano/db` and `./cardano/kupo` first;
the bootstrap refuses to overwrite existing data implicitly.
