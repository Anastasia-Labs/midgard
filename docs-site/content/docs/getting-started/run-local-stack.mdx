One guided happy path from a fresh checkout to a running local Midgard node;
each step links the page that owns the details. For the acceptance-grade
version of this flow, with run modes, evidence artifacts, and failure routing,
use the [End-to-End Testing Flow](/docs/operators/node/e2e-testing-flow) instead.

<Callout type="warn" title="Current release prerequisite">
  This sequence is a deployment target. The current consensus profile has no
  accepted release-evidence digest, so committee startup fails its release
  readiness check. Confirm that prerequisite before funding or initializing a
  deployment; the current checkout cannot complete the full flow below.
</Callout>

## What you will have at the end

A local Cardano preprod backend (node, Ogmios, Kupo), an initialized Midgard
deployment on it, one registered and active operator, and a Midgard node
answering on its readiness endpoint.

<Steps>

<Step>
### Get the code and toolchain

Follow [Getting the code](/docs/getting-started/local-dev): clone the
repository and install Node.js, `pnpm`, Docker with Compose v2, and Aiken.

</Step>

<Step>
### Bring up the L1 backend

Follow [L1 Backend](/docs/getting-started/l1-backend): copy `.env.example` to
`.env` in `l1-services/`, fill in the two Mithril verification keys, and run:

```sh
cd l1-services
docker compose up -d
```

The first start downloads a Cardano DB snapshot; wait until Ogmios (port 1337)
and Kupo (port 1442) are synchronized and pass the provider preflight before
continuing. A reachable port alone does not establish chain freshness.

</Step>

<Step>
### Build the on-chain code and the workspace

From the repository root, compile the Aiken contracts with the `testnet`
environment, then build the TypeScript workspace:

```sh
cd onchain/aiken && aiken build --env testnet
cd ../../demo && pnpm install --frozen-lockfile && pnpm run build
```

See [Local Development](/docs/getting-started/local-dev) for the full command
reference.

</Step>

<Step>
### Initialize the protocol

Configure the node (see
[Initialization &amp; Deployment](/docs/operators/node/initialization-deployment);
keep `RUN_GENESIS_ON_STARTUP=false`). Start PostgreSQL and install its schema
with `node dist/index.js db:migrate` from `demo/midgard-node`; startup verifies
the schema rather than creating it. Prepare the funded one-shot nonce and
reference scripts through that deployment guide, then initialize:

```sh
node dist/index.js init \
  --contract-deployment-info-output deploymentInfo/contract-deployment-info.json
```

`init` performs one atomic bootstrap for an empty topology. A complete topology
returns `already-initialized` after ensuring PHAS reward-account registration;
a partial topology fails. Use `deployment-status` to reconcile the existing
identity before attempting further state changes.

</Step>

<Step>
### Register and activate an operator

```sh
node dist/index.js register-active-operator
node dist/index.js activate-operator
```

The [CLI Reference](/docs/operators/node/cli-reference) documents both commands
and the operator lifecycle around them.

</Step>

<Step>
### Start the committee and node, then confirm readiness

Configure and start the separate [DA committee](/docs/watchers/da-committee-node)
against the same deployment identity. Attestation and later merges require that
service; the operator node alone does not provide it. From `demo/midgard-node`:

```sh
node dist/index.js listen
```

The node is up when `/readyz` reports ready with no readiness reasons and
`/healthz` reports healthy. The
[Server &amp; HTTP API](/docs/operators/node/server-http-api) page lists both
endpoints.

</Step>

</Steps>

<Callout type="warn" title="Preprod deployment">
  The backend runs locally but follows the shared Cardano Preprod network.
  Protocol initialization submits real Preprod transactions using the Aiken
  `testnet` parameters; this is not an isolated local devnet. See [Project
  Status](/docs/getting-started/status) for what remains open.
</Callout>
