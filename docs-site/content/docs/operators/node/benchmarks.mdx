Node package scripts measure individual pipeline stages. External stress and
acceptance commands live in the separate `midgard-node-tools` binary; they do
not ship in the operator binary. See each package's `package.json` and README
for the maintained invocation and prerequisites.

<Callout type="warn" title="What a benchmark run does not prove">
  A throughput measurement proves only its declared workload and environment.
  Separate process/recovery acceptance gates exercise restart and rollback; a
  throughput score cannot replace them. Formal scenarios impose exact profile,
  corpus and environment requirements. Record the artifact identity, conditions
  and date alongside any number you quote. See [Project
  Status](/docs/getting-started/status) for what remains unproven.
</Callout>

## Commands & scripts

The following commands run through `midgard-node-tools`:

- `e2e-start-service` · `e2e-run-step` · `e2e-finalize-summary`, run and summarize
  end-to-end scenarios.
- `e2e-stress-l2-throughput`: stress-test L2 transaction throughput.
- `stress-wallets:prepare`: prepare wallets for stress runs.

The operator command `audit-blocks-immutable` checks the linkage between block
membership and immutable transaction payloads.

For large-scale load generation, use the stress and e2e commands of the
`demo/midgard-node-tools` package (see its `README.md`).

The `e2e-*` commands here are the building blocks of the full
[End-to-End Testing Flow](/docs/operators/node/e2e-testing-flow), which drives a
complete deposit / L2 / DA / merge acceptance run.
