---
title: "Server HTTP API"
description: "The HTTP routes exposed by the Midgard node: unauthenticated routes for submission and queries, and admin-gated routes for initialization and operational control."
---

The `listen` command starts the node's HTTP server together with all background
fibers. Every route below is registered in `src/commands/listen-router.ts`.

## Starting the listener

```sh
# Build and start the server plus background fibers.
pnpm listen

# Or directly, with monitoring (Prometheus + OpenTelemetry) enabled.
node dist/index.js listen --with-monitoring
```

The server binds the port from `PORT` in your environment (the examples use
`http://127.0.0.1:3000`). With `--with-monitoring`, Prometheus metrics are also
served on `PROM_METRICS_PORT` at `/metrics`.

## Access control

Routes fall into two classes. Public routes need no credentials. Admin routes are
gated by `ADMIN_API_KEY` and require the key in the `x-midgard-admin-key` request
header; a missing or wrong key is denied before the handler runs.

"Public" here means unauthenticated, not safe to expose to the open internet. TLS,
rate limiting, and ingress hardening are
[readiness blockers](/docs/getting-started/status), not solved problems.

<Callout type="warn" title="Always set ADMIN_API_KEY on shared nodes">
`ADMIN_API_KEY` gates the admin-only HTTP surface (init, commit, merge, state
queue inspection, mutation-lease coordination, and log routes). Keep it set in
any shared or remotely reachable environment.
</Callout>

## Public routes

### Health and readiness

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/healthz` | Liveness only: confirms the server is running. |
| `GET` | `/readyz` | Readiness: worker heartbeats, admission backlog/age, unfinished mutation jobs, unresolved block submissions, DB connectivity, provider reachability, and mutation-lease state. Returns `503` until ready. |
| `GET` | `/protocol-info` | Stable public facts external transaction builders need (includes the current slot). |

### Transaction submission and status

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | `/submit` | Validate, normalize, and enqueue a submitted L2 transaction. Body must be raw Midgard canonical transaction CBOR with `Content-Type: application/cbor`. |
| `GET` | `/tx-status` | Resolve the node's canonical status for a transaction (`?tx_hash=...`). |
| `GET` | `/tx` | Return the CBOR for a known tx hash from mempool or immutable storage (`?tx_hash=...`). |
| `GET` | `/txs` | Return the address-history tx payloads for an address (`?address=...`). |

`POST /submit` responses are explicit: `202` for a newly admitted transaction,
`200` for a duplicate, `415` when the content type is not `application/cbor`,
`400` for an invalid or non-normalizable payload, `409` on a tx-id byte
conflict, and `503` when the durable admission backlog is full.

### UTxO and ledger queries

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/utxos` | Spendable mempool-ledger UTxOs for an address (`?address=...`). |
| `GET` | `/utxo` | One spendable mempool-ledger UTxO by raw TxOutRef CBOR hex (`?txOutRef=...`). |
| `POST` | `/utxos?by-outrefs` | Spendable UTxOs for a requested list of `txHash#outputIndex` references, supplied in the JSON body. |
| `GET` | `/block` | Tx hashes referenced by a committed block header (`?header_hash=...`). |
| `GET` | `/deposit-status` | One serialized deposit row by event id or L1 tx hash. |

### Building an unsigned deposit

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | `/deposit/build` | Build an unsigned L1 deposit transaction from a caller-supplied wallet view and return CBOR for external signing. |

The caller supplies the funding address plus the exact wallet UTxOs that may be
spent; the node holds no signing key and returns `unsignedTxCbor` for the caller
to sign externally.

```sh
curl -X POST http://127.0.0.1:3000/deposit/build \
  -H 'content-type: application/json' \
  -d '{
    "l2Address": "addr_test1...",
    "lovelace": "12000000",
    "fundingAddress": "addr_test1...",
    "fundingUtxos": [
      {
        "txHash": "11...11",
        "outputIndex": 0,
        "address": "addr_test1...",
        "assets": { "lovelace": "30000000" }
      }
    ]
  }'
```

Optional body fields include `l2Datum` (even-length hex inline datum; Midgard L2
outputs support only absent or inline datums, never datum-hash outputs),
`additionalAssets` (an array of `{ unit, amount }`), and per-UTxO
`datumHash` / `datum` / `scriptRef` hex fields preserved in the external wallet
view.

## Admin routes

All routes below require the `x-midgard-admin-key` header matching
`ADMIN_API_KEY`.

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/init` | Initialize protocol state when startup policy and on-chain topology allow it. Refuses over invalid existing topology. |
| `GET` | `/commit` | Trigger a manual block commitment. |
| `GET` | `/merge` | Trigger a manual merge of the oldest queued block into confirmed state. |
| `GET` | `/stateQueue` | Log and return the current ordered state-queue headers plus merge-readiness. |
| `GET` | `/stateQueueMutationLease` | Inspect the state-queue mutation lease (`?recent_limit=...`). |
| `POST` | `/stateQueueMutationLease` | Coordinate external state-queue mutators (`inspect`, `acquire`, `renew`, `release`, `fail`) for flows such as manual fault-proof removal. |
| `GET` | `/logBlocksDB` | Log a compact summary of block-link rows. |
| `GET` | `/logGlobals` | Log the current process-global coordination state. |

<Callout type="info" title="The mutation lease is a safety interlock">
The state-queue mutation lease is a mutual-exclusion token. External mutators (for
example a manual fault-proof removal) must `acquire` the lease, do their work, then
`release` it. A busy lease returns `409`. The node's readiness check treats a stale
active lease as a reason to stay not-ready.
</Callout>
