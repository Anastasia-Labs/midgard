When the node runs `listen`, it starts a set of **background fibers** that drive the
protocol forward. The worker modules are defined in `src/fibers/`, and
`src/commands/listen.node-fibers.ts` lists every fiber `listen` runs.

The table below covers the fibers that drive protocol work. The listener also
starts the L1 follower and its follower-change driver, the write-behind
service, the HTTP server, the configured retained-payload server and smaller
helpers (admission retention, the L1 provider readiness refresher, the import
checker); this table is not a count of every running fiber.
`monitor-mempool` and `alert-signals` run only when the node is started with
`-m` / `--with-monitoring`.

Deposit and withdrawal discovery and deposit projection are not fibers. The
node's L1 follower projects deposit and withdrawal events from the chain it
follows, and on each follower change the follower-change driver writes them
into the node database and, in the same transaction, projects the deposits
whose inclusion time is due. Projected outputs stay hidden from spendable
queries until confirmation assigns their block header.

Forced transaction orders are not a fiber either. The follower records each
order and its field carriage from the block that created it; the same driver
then rebuilds the order's transaction and writes it into the node database.
Carriage published in an earlier block is read from the ledger at the order
block's parent, then at the tip, and failing both from the follower's stored
transactions or the `L1_TX_CONTENT_SOURCES` endpoints, whose answers are
accepted only when they hash to the requested transaction id. Until every
carriage resolves, `/readyz` reports `forced_order_carriage_pending` and the
driver retries; an order that cannot be rebuilt reports
`forced_order_ingestion_failed`. Neither stops the process. Block commitment
never claims an end time past the events the follower has ingested, nor at or
past the inclusion time of a live forced order the node has not yet written.

## The fibers

| Fiber                            | Drives                                                                                                                                                                                                                                                                                                                                                                        | One-shot equivalent                                 |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `admission-backlog-gauge`        | Refreshes the hybrid durable-admission backlog count used for admission-cap decisions and metrics.                                                                                                                                                                                                                                                                            | None                                                |
| `attestation-timeout-correction` | Observes unattested state-queue heads and submits the timeout correction when due. Each tick builds the next step from the chain; a failed step is retried on the next tick.                                                                                                                                                                                                  | None                                                |
| `block-commitment`               | Batches mempool activity and commits a block header to the L1 state queue.                                                                                                                                                                                                                                                                                                    | Admin `POST /commit`                                |
| `da-publication-reconciler`      | Seeds and retries durable per-peer DA payload deliveries, then publishes announcements after the committee threshold accepts the payload. It remains idle when no DA publication manifest is configured.                                                                                                                                                                      | None                                                |
| `merge`                          | Merges matured blocks in an eligible DA state (Attested or Published) into confirmed state.                                                                                                                                                                                                                                                                                   | None                                                |
| `tx-queue-processor`             | Drains the durable admission queue into validation and the mempool.                                                                                                                                                                                                                                                                                                           | None                                                |
| `l2-tx-peer-forwarder`           | Shares pending L2 transactions with the operators named in `L2_TX_PEERS`, so whichever operator holds the next shift can commit them. All state is in memory.                                                                                                                                                                                                                 | None                                                |
| `settlement`                     | Runs withdrawal and payout settlement jobs in a worker thread. See [Deposits &amp; Withdrawals](/docs/operators/node/deposits-withdrawals).                                                                                                                                                                                                                                   | None                                                |
| `validation-trace-defense`       | Defends this operator's blocks in validation-trace disputes, earliest deadline first.                                                                                                                                                                                                                                                                                         | None                                                |
| `confirmed-ledger-verification`  | Verifies the landed ledger against its stored roots off the commit path; commits on a landed tail wait until a pass holds.                                                                                                                                                                                                                                                    | None                                                |
| `retention-sweeper`              | Removes retention-expired data, subject to the DA retention guards.                                                                                                                                                                                                                                                                                                           | None                                                |
| `monitor-mempool`                | Emits mempool metrics. Started only with `--with-monitoring`.                                                                                                                                                                                                                                                                                                                 | None                                                |
| `native-mpf-owner-supervisor`    | Stops the node once the native MPF owner reports a terminal failure, so the process supervisor restarts it from its durable marker.                                                                                                                                                                                                                                           | None                                                |
| `operator-watchdog`              | Strikes the scheduled operator when its shift is missed and hands the shift on; force-retires an operator at the strike limit once the patience window has passed. On by default (`OPERATOR_WATCHDOG_ENABLED`), successor acts at the threshold, other active nodes after `OPERATOR_WATCHDOG_PATIENCE_MS`. See [Operator Lifecycle](/docs/operators/node/operator-lifecycle). | `strike-inactive-operator`, `force-retire-operator` |

Each fiber runs on its own schedule, configured through the node's environment (for
example `WAIT_BETWEEN_MERGE_TXS` for `merge`). By default,
`tx-queue-processor` polls every 250 ms and `admission-backlog-gauge` every 500 ms,
`monitor-mempool` every second, and `da-publication-reconciler` every 30
seconds.

<Callout type="warn" title="attest-state-queue-once is not a fiber">
  DA attestation is not driven by a background fiber. `attest-state-queue-once`
  is an operator-local command that signs with locally held committee keys,
  submits signatures, and applies a threshold attestation. The governed
  threshold is at least two, so one key alone cannot complete it. A real
  deployment attests through the [DA committee
  node](/docs/watchers/da-committee-node). See the [end-to-end testing
  flow](/docs/operators/node/e2e-testing-flow).
</Callout>

## When a fiber stalls

No fiber fails the process: a condition a fiber cannot resolve raises a named
liveness reason, and the fibers that condition must stop are held until it
clears. A stall therefore leaves the process alive.

`GET /readyz` tracks heartbeats for commitment, merge and
admission processing, along with other readiness conditions. It does not provide a distinct heartbeat for every module in this
table. Inspect its reasons and the relevant worker logs, not only `/healthz`.

For a blocked merge, inspect its reported blocker and the `stateQueueMutationLease`
field of `/readyz` before restarting. A lease is one possible cause. See
[Server HTTP API](/docs/operators/node/server-http-api).
