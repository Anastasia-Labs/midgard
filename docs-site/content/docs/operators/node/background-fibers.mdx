When the node runs `listen`, it starts a set of **background fibers** that drive the
protocol forward. The worker modules documented here are defined in
`src/fibers/`, exported through
`src/fibers/index.ts`, and launched together near the end of
`src/commands/listen.ts`.

The seventeen long-running fibers exported by `src/fibers/index.ts` are listed
below. The listener also starts the write-behind service, HTTP server and configured
retained-payload server; this table is not a count of every running fiber. `monitor-mempool` runs only when the node is started
with `-m` / `--with-monitoring`. `speculative-commit-builder` and
`user-event-barrier-refresher` run only with `SPECULATIVE_COMMIT_BUILD=true`;
that setting is disabled by default and cannot be combined with the legacy MPF
engine. The speculative-commit module also starts its companion submitter loop
under the same flag.

## The fibers

| Fiber                                | Drives                                                                                                                                                                                                                                                                                                                                    | One-shot equivalent                                 |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `admission-backlog-gauge`            | Refreshes the hybrid durable-admission backlog count used for admission-cap decisions and metrics.                                                                                                                                                                                                                                        | None                                                |
| `attestation-timeout-correction`     | Observes unattested state-queue heads, submits timeout correction when due, and reconciles finalized or retracted correction transitions.                                                                                                                                                                                                 | None                                                |
| `block-commitment`                   | Batches mempool activity and commits a block header to the L1 state queue.                                                                                                                                                                                                                                                                | Admin `GET /commit`                                 |
| `block-confirmation`                 | Advances committed block headers through confirmation.                                                                                                                                                                                                                                                                                    | `reconcile block-committed` (inspection/recovery)   |
| `da-publication-reconciler`          | Seeds and retries durable per-peer DA payload deliveries, then publishes announcements after the committee threshold accepts the payload. It remains idle when no DA publication manifest is configured.                                                                                                                                  | None                                                |
| `merge`                              | Merges matured blocks in an eligible DA state (Attested or Published) into confirmed state.                                                                                                                                                                                                                                               | Admin `GET /merge`                                  |
| `tx-queue-processor`                 | Drains the durable admission queue into validation and the mempool.                                                                                                                                                                                                                                                                       | None                                                |
| `fetch-and-insert-deposit-utxos`     | Reads L1 deposit UTxOs and records them locally.                                                                                                                                                                                                                                                                                          | None                                                |
| `fetch-and-insert-withdrawal-utxos`  | Reads L1 withdrawal-order UTxOs and records them locally.                                                                                                                                                                                                                                                                                 | `fetch-withdrawals-once`                            |
| `fetch-and-insert-tx-order-utxos`    | Reads L1 transaction-order UTxOs and records them locally.                                                                                                                                                                                                                                                                                | None                                                |
| `project-deposits-to-mempool-ledger` | Projects visible deposits once inclusion time is due; outputs remain hidden from spendable queries until confirmation assigns their block header.                                                                                                                                                                                         | `project-deposits-once`                             |
| `retention-sweeper`                  | Removes retention-expired data, subject to the DA retention guards.                                                                                                                                                                                                                                                                       | None                                                |
| `monitor-mempool`                    | Emits mempool metrics. Started only with `--with-monitoring`.                                                                                                                                                                                                                                                                             | None                                                |
| `mpf-payload-audit`                  | When MPF_PAYLOAD_ROOT_CHECK is enabled, audits the confirmed-ledger MPF root on its block/time schedule; divergence records the sticky commit halt. Legacy-engine audits are skipped.                                                                                                                                                     | `mpf-audit`                                         |
| `speculative-commit-builder`         | With `SPECULATIVE_COMMIT_BUILD=true`, prebuilds the next block candidate while the current block confirms; its companion submitter uses the normal mutation lease after confirmation.                                                                                                                                                     | None                                                |
| `user-event-barrier-refresher`       | With `SPECULATIVE_COMMIT_BUILD=true`, reconciles deposits, withdrawals, and transaction orders into monotone barrier watermarks used by speculative builds.                                                                                                                                                                               | None                                                |
| `operator-watchdog`                  | Strikes the scheduled operator when its shift is missed and hands the shift on; force-retires an operator at the strike limit once the patience window has passed. On by default (`OPERATOR_WATCHDOG_ENABLED`), successor acts at the threshold, other active nodes after `OPERATOR_WATCHDOG_PATIENCE_MS`. See [Operator Lifecycle](/docs/operators/node/operator-lifecycle). | `strike-inactive-operator`, `force-retire-operator` |

Each fiber runs on its own schedule, configured through the node's environment (for
example `WAIT_BETWEEN_MERGE_TXS` for `merge`). By default,
`tx-queue-processor` polls every 250 ms and `admission-backlog-gauge` every 500 ms,
`monitor-mempool` every second, `user-event-barrier-refresher` every two seconds,
and `da-publication-reconciler` every 30 seconds. The speculative builder and its
submitter are queue-driven. `mpf-payload-audit` wakes at the shorter of the MPF
audit time interval and the block-commitment interval, then audits only when the
configured block-or-time threshold is due.

<Callout type="warn" title="attest-state-queue-once is not a fiber">
  DA attestation is not driven by a background fiber. `attest-state-queue-once`
  is an operator-local command that signs with locally held committee keys,
  submits signatures, and applies a threshold attestation. The governed
  threshold is at least two, so one key alone cannot complete it. A real
  deployment attests through the [DA committee
  node](/docs/watchers/da-committee-node). See the [end-to-end testing
  flow](/docs/operators/node/e2e-testing-flow).
</Callout>

## When a fiber stalls

Many worker loops log and retry expected failures; a stall can leave the process
alive. Unhandled failures can also terminate the composed listener program.

`GET /readyz` tracks heartbeats for commitment, confirmation, merge, deposit
fetch, withdrawal fetch and admission processing, along with other readiness
conditions. It does not provide a distinct heartbeat for every module in this
table. Inspect its reasons and the relevant worker logs, not only `/healthz`.

For a blocked merge, inspect its reported blocker and the admin-gated
`GET /stateQueueMutationLease` before restarting. A lease is one possible cause. See
[Server HTTP API](/docs/operators/node/server-http-api).
