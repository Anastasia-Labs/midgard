The operator binary is `midgard-node`; the separate `midgard-node-tools` binary
owns wallet generation, stress workloads and E2E orchestration. From either
package directory, `node dist/index.js --help` lists that binary's commands.
Build the relevant package first. Use a command's `--help` for required options.

The 52 commands explicitly registered in the operator entry point are joined by
generated reference-script publication commands. The groups below distinguish
operator commands, nested reconciliation commands, and separate tooling.

## Operator runtime and deployment

Run these through `midgard-node`:

- `listen`
- `init` · `export-contract-deployment-info` · `deployment-status`
- `prepare-hub-oracle-one-shot-nonce`
- `reference-script-wallet-status` · `sweep-reference-script-wallet`
- `deploy-reference-script-<name>`: generated publication commands; use the
  binary's help for the configured list.
- `register-operator` · `activate-operator` · `register-active-operator`
- `operator-status` · `retire-operator` (`deactivate-operator`) ·
  `recover-operator-bond` (`unlock-operator`) · `deregister-operator`
- `strike-inactive-operator` · `force-retire-operator` ·
  `slash-duplicate-operator`; see [Operator Lifecycle](/docs/operators/node/operator-lifecycle)
- `register-phas-membership-reward-account`

See [Initialization & Deployment](/docs/operators/node/initialization-deployment)
and [Server HTTP API](/docs/operators/node/server-http-api).

## Operator database, user events and settlement

- `db:migrate` · `db:status` · `db:verify` · `db:checksum` · `db:backfill-da-payloads`
- `submit-l2-transfer` · `submit-deposit` · `submit-withdrawal` · `withdrawal-status`
- `project-deposits-once` · `fetch-withdrawals-once` · `reconcile-deposit-submission`
- `resolve-event-settlement-proof` · `absorb-confirmed-deposit-to-reserve`
- `initialize-payout` · `add-reserve-funds-to-payout` · `conclude-payout`
- `payout-status` · `reserve-utxos`
- `address-from-seed` · `utxos` · `l1-utxos` · `l1-provider-preflight`
- `audit-blocks-immutable` · `mpf-audit` · `mpf-replay`
- `da-libp2p-preflight` · `da-libp2p-generate-manifest`
- `availability-challenge`: open, respond, settle, close, time out, inspect or recover a DA challenge using an isolated actor wallet.

`commit-explicit-block-header` is a separately acknowledged drill command for
caller-supplied roots, not the ordinary mempool commitment command.
`attest-state-queue-once` uses locally held committee keys; it does not replace
independent committee acceptance. Ordinary operation uses the background fibers.

## Operator reconciliation

These are subcommands of `reconcile`, not top-level commands:

- `reconcile phas-registered`
- `reconcile reference-scripts-complete`
- `reconcile deployment-manifest`
- `reconcile deposit-projected`
- `reconcile tx-committed`
- `reconcile da-attested`
- `reconcile block-committed`
- `reconcile retention-check`
- `reconcile local-finalization`
- `reconcile merge-complete`

Inspect the result before selecting an available `--repair` action. Read-only
inspection does not imply that a repair ran or a milestone completed.
