title: "DA & Oracle"
description: "Building data-availability attestation/payload, hub-oracle, initialization, and escape-hatch transactions."
---

These modules cover data availability, the hub oracle, and protocol bootstrap/escape
flows. Datum/redeemer schemas use Lucid `Data`; transaction programs and payload
codecs are separate APIs.

## Data availability

- **`da-attestation`**: build DA attestation transactions recording that block data is
  available. Exports `DaParamsDatum`, `DaAttestationDatum`, and constants such as
  `DA_ATTESTATION_ASSET_NAME_PREFIX` and
  `EMPTY_ATTESTED_SIGNER_BITMAP`. Enforced on L1 by the
  [`da-attestation` validator](/docs/onchain/da-validators).
- **`da-payload`**: encode/decode retained payloads and validation witnesses;
  this is payload data, not an L1 transaction builder.
- **`availability-challenge`**: typed availability commitments, status, bond and
  challenge schemas used by the attestation lifecycle. Deployment acceptance is
  separate from the presence of these SDK types.

## Hub oracle and bootstrap

- **`hub-oracle`**: transactions against the central config/nonce authority. Exports
  `HubOracleDatum`, the `makeHubOracleDatum` / `makeHubOracleOneShotNonceDatum`
  helpers, `utxosToHubOracleUTxOs`, and `incompleteHubOracleInitTxProgram`.
- **`initialization`**: one-time protocol initialization, via
  `incompleteInitializationTxProgram` and `unsignedInitializationTx`.
- **`escape-hatch`**: currently only the `ESCAPE_HATCH_ASSET_NAME` constant.
  It does not implement a user force-exit or operator-halt recovery flow.
