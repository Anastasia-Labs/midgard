`demo/da-committee-node` stores and verifies canonical block payloads, signs
availability commitments, and exchanges payloads and attestations over libp2p.
The independent [watcher](/docs/watchers/concept) retrieves this evidence and
checks L2 execution against authenticated L1 commitments.

The `threshold-mirror-v1` profile requires public retention for at least 14 days.
A threshold signature is a committee commitment; it does not by itself prove
that bytes remain publicly retrievable. Deployment and end-to-end acceptance
remain subject to [Project Status](/docs/getting-started/status).

## Contract boundary

The DA params governor authenticates a sorted, unique packed committee of
32-byte Ed25519 verification keys, its hash, the threshold, and governance
owners. An attestation certificate carries the header hash, an
`availability_commitment`, the pinned committee hash and threshold, a signer
bitmap and count, and a rescue beneficiary.

`AddSignatures` verifies packed `signer_index_u8 || signature_64_bytes`
witnesses with strictly ascending indexes. The signed message is:

```text
blake2b256(
  UTF8("MidgardDaAvailabilityAttestationV1")
  ++ serialise_data(availability_commitment)
)
```

The commitment binds the deployment identity, header hash, payload length,
response geometry, tranche descriptors, and bond owner. Use
`daAvailabilityAttestationMessage` from `@al-ft/midgard-sdk`; the older
`encodeDaAttestationPreimage(headerHash)` transport helper is not this contract's
signing message.

`ApplyToStateQueue` checks quorum against the current governed committee and
threshold, burns the attestation token, and cross-binds the availability policy's
`MintBondFromAttestation` action. Queue availability is a typed lifecycle:
`Unattested`, `Attested`, `Challenged`, or `Published`, with the corresponding
bond/challenge identifiers or terminal commitment. It is not a policy-id marker.
Committee rotation invalidates a stale certificate; the rescue branch returns
its value to the certificate's pinned rescue beneficiary.

The contracts bind attestations and availability state transitions. They do not
run libp2p retrieval or inspect the committee's database. See the
[DA validators](/docs/onchain/da-validators) and the SDK's
`availability-challenge.ts` for the current schemas.

## Publish, retain, and retrieve

The committee validates the payload's deployment identity, canonical encoding,
roots and counts, reconstructs its header, and matches that header to L1 before
signing. Storage and retrieval readiness must precede signing. The exact
retained envelope and payload schemas live in the SDK DA codecs; derived trace
and execution material must be checked against the commitments they support.

The committee runtime wires libp2p transport, payload validation and storage,
peer signature coordination, the on-chain coordinator, and submitter
reconciliation. The process API provides health/readiness and manifest surfaces;
DA protocol bytes travel over libp2p only.

The runtime runs retention checks and exposes readiness/deadline evidence.
Currently `src/index.ts` supplies no authenticated active-challenge authority to
the retention decision, so it holds every payload. Reaching 14 days does not
authorize pruning. The source labels that missing deployed authority Q58.

## Dedicated public reader

Public retrieval runs in the separate `midgard-public-retained-da` process.
It serves TCP/Noise/Yamux requests from a PostgreSQL reader role. It does not
load the committee signer, submitter, or mutable store configuration.

After installing the demo workspace, build the package from the repository root:

```bash
pnpm --dir demo --filter da-committee-node... build
```

Configure the dedicated reader's service environment with all of:

| Variable                                   | Required value                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `DA_PUBLIC_RETAINED_DA_ENABLED`            | `true`                                                                                                 |
| `MIDGARD_DEPLOYMENT_MANIFEST_PATH`         | Runtime manifest with `runtime_topology.target = "committee"` and `public_retained_da`.                |
| `MIDGARD_CONTRACT_DEPLOYMENT_INFO_PATH`    | Matching finalized contract deployment manifest with the exact V1 consensus profile.                   |
| `DA_PUBLIC_RETAINED_DA_PRIVATE_KEY_SOURCE` | Dedicated `seed:`, `hex:`, or `file:` libp2p key source matching the manifest's public reader peer id. |
| `DA_PUBLIC_RETAINED_DA_DATABASE_URL`       | PostgreSQL connection using the dedicated reader credentials.                                          |
| `DA_PUBLIC_RETAINED_DA_DATABASE_ROLE`      | Exact PostgreSQL reader role name.                                                                     |

The database role must have `SELECT` and no DML privileges on
`committee_da_payloads` and `committee_state_queue_headers`; startup verifies role and
privilege constraints. File stores are unsupported. Do not pass
`DA_COMMITTEE_DB_PATH` or `DA_COMMITTEE_DATABASE_URL` to this process: the configuration
loader rejects either variable. Keep its environment separate from committee
credentials.

With that environment supplied by the service manager, start from the repository root:

```bash
node demo/da-committee-node/dist/public-retained-da.js
```

The executable accepts no arguments other than `--help`. Matching manifests,
release-ready consensus configuration, database permissions, peer identity, and
listener startup are prerequisites; a listening process alone is not retrieval
acceptance evidence.

## Protocol routes

Topics and request-response routes are deployment-scoped:

```text
/midgard/{deployment_fingerprint}/da/payload-announcements/1
/midgard/{deployment_fingerprint}/da/attestations/1
/midgard/{deployment_fingerprint}/da/conflicts/1

/midgard/{deployment_fingerprint}/da/payload-submit/1
/midgard/{deployment_fingerprint}/da/payload-by-header/1
/midgard/{deployment_fingerprint}/da/payload-chunk/1
/midgard/{deployment_fingerprint}/da/metadata-by-header/1
/midgard/{deployment_fingerprint}/da/proof-bundle-by-header/1
/midgard/{deployment_fingerprint}/da/attestations-by-header/1
```

These describe the committee transport surface, not permission to expose its
write routes on the public reader. The reader enables only its manifest's
allowed retrieval protocols, with per-peer and global request limits. Exact
schemas, route constructors, and bounds live in
`@al-ft/midgard-core/da-transport`. See [DA transport rules](/docs/watchers/da-transport).

A watcher must authenticate the L1 header and its availability state, retrieve
matching retained bytes, and reconstruct the committed roots. Missing or
inconsistent DA remains non-actionable evidence and can prevent a supported
proof before maturity; it must never be treated as a successfully verified block.
