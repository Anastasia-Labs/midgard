**Midgard** is Cardano's first optimistic rollup protocol, a Layer 2 that batches
user transactions off-chain, commits compact block headers to Layer 1, and relies
on an **optimistic security model**: blocks are assumed valid unless a watcher
submits a fraud proof that an on-chain validator can resolve.

This documentation covers the main parts of the repository, from the developer SDK
down to the on-chain validators and the formal protocol specification.

## Documentation map

- **Getting Started**: what Midgard is, the repository layout, local dev setup,
  the L1 backend, and testnet-readiness status.
- **Developer SDK**: `lucid-midgard` (native transaction builder), `midgard-core`
  (protocol primitives and the native transaction codec), and `midgard-sdk`
  (operator and watcher transaction builders).
- **Validation Engine**: the Phase A / Phase B pipeline that validates queued L2
  transactions.
- **Operators**: running the Midgard node and its load-generation tooling.
- **Watchers & Data Availability**: the libp2p DA committee that lets watchers verify
  availability and challenge invalid commitments.
- **Fault Proofs**: the tooling and protocol for challenging invalid blocks.
- **On-Chain Validators**: the Aiken and Plutarch validators that enforce the
  protocol on Layer 1.
- **Protocol Specification**: the normative architecture target, with explicit
  conformance and implementation-status caveats.
