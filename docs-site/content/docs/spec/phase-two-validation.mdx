Chapter 7 specifies **phase-two validation**, the deep validation of L2 state and
script execution that fraud proofs rely on. It is the most involved part of the
protocol because it must be reproducible both off-chain (to detect fraud) and on-chain
(to adjudicate a single step of it cheaply).

## State representation

- **Term Representation**: how UPLC terms and state are represented for verification.
- **Decoding Steps**, **Execution Steps**, **Execution Trace**: how off-chain data is
  decoded and executed to reconstruct the exact evaluation, producing a trace that a
  proof can index into.

## Script execution and the proof boundary

The chapter's current proof-boundary section describes the V1 validation-trace
dispute: opening authenticates the descriptor and source against the challenged
header; signed operator and challenger moves narrow an interval; one-step
resolution checks the instruction from the agreed pre-state. Timeout and
challenge-opening deadlines are part of that state machine.

Its coverage includes source resolution, purpose/redeemer binding, integrity,
native scripts, CEK execution, protected receive, observers, minting, budgets,
and the resulting ledger delta. Source machinery and a specified dispute do not
establish release acceptance. Current evidence must bind exact validators,
deployment/profile identity, negative tests, and worst-case size/execution
measurements. See [Project Status](/docs/getting-started/status) and the
[catalogue status](https://github.com/Anastasia-Labs/midgard/blob/main/docs/fault-proofs/catalogue-status.md).

## In the codebase

The off-chain counterpart is the [validation engine](/docs/validation/overview): its Phase B
stage constructs script contexts and uses the structural CEK executor for
canonical V1 program material, and
[`midgard-validation`](/docs/validation/overview) exposes the public validation
surface. On L1, the reconstructed step is adjudicated by the
[computation-thread fraud-proof machines](/docs/onchain/fraud-proof-machines), using
[Aiken membership proofs](/docs/onchain/phas-membership) to reference committed state.
