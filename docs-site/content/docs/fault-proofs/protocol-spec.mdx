The fault-proof tooling is the off-chain driver for the protocol defined in
Chapters 4 and 7 of the specification:
[Proof Protocol](/docs/spec/proof-protocol) and
[Phase-Two Validation](/docs/spec/phase-two-validation).

## The model

- **Fraud-proof catalogue**: the enumerated categories of invalidity a block can be
  challenged for (double-spend, invalid-range, missing/invalid signatures, min-fee,
  no-input / zero-input, reference-input issues, and more).
- **Computation thread**: a single-threaded state machine that steps a proof to a
  verdict across multiple transactions, so verification cost is bounded per
  transaction. Its token is minted when the challenge opens and burned when the proof
  concludes.
- **Fraud-proof tokens**: minted on the final step, once the computation thread has
  succeeded. A `fraud_proof` token is the permanent record of a concluded proof, not
  authorization to begin one.
