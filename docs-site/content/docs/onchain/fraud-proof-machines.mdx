Midgard's optimistic security is enforced by a family of on-chain validators that
adjudicate challenges against invalid blocks. They implement the
[Proof Protocol](/docs/spec/proof-protocol).

## Core validators

- **`computation-thread`**: the single-threaded state machine that steps a proof
  through verification across multiple transactions. Its token is minted when a
  challenge opens and burned when the proof succeeds.
- **`fraud-proof`**: mints the permanent fraud-proof token on the final step, once the
  computation thread has succeeded. The token records a concluded proof; it does not
  authorize a challenge.
- **`fraud-proof-catalogue`**: the catalogue enumerating the invalidity categories
  a block may be challenged for.

## Per-category step machines

Under `onchain/aiken/validators/fraud-proofs/`, each invalidity category is a
multi-step machine (`step-0N.ak`). The categories present in the source are:

`double-spend` · `input-no-idx` · `invalid-range` · `invalid-signature` ·
`min-fee` · `missing-native-script-tx` · `missing-signature` · `no-input` ·
`no-reference-input` · `withdrawn-reference-input` · `zero-input` ·
plus a `transition-trace` proof.

<Callout type="warn" title="Source files are not deployed coverage">
  The seven deployed catalogue categories, in immutable ID order, are
  `doubleSpend`, `nonExistentInput`, `nonExistentInputNoIndex`, `invalidRange`,
  `transitionTrace`, `zeroInput`, and `validationTraceDispute`. Other compiled
  source directories are not registered coverage, and the minimum-fee proof
  contains a stubbed check. Treat the [fault-proof
  audit](/docs/fault-proofs/overview), not the source-directory list, as the
  coverage statement.
</Callout>
