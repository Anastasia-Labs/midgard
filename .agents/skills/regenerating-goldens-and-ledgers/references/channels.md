# Generated-artifact channels

Every committed file that a script, test or compiler writes, as of 2026-09-25.
The machine-readable copy is [`../scripts/channels.json`](../scripts/channels.json);
`affected-channels.mjs --verify-table` fails when the tree grows a generator,
ledger or generated file that neither lists nor ignores
[script: .agents/skills/regenerating-goldens-and-ledgers/scripts/affected-channels.mjs].
This page is the prose half: what each channel pins, where CI runs its check, and
what makes it stale. Commands run from the repository root.

Two terms used throughout:

- **Whole module**: the generator emits the entire Aiken file, which carries a
  "Generated by" header. Nothing in it is hand-written.
- **Rebind**: the generator rewrites named `const` values inside a hand-written
  Aiken module (`rebindAikenConstants`,
  `demo/midgard-core/scripts/golden-channel.mjs:149`). The rest of the module is
  hand-written, and nothing in the file shows which constants are generated. A
  rebind target that no longer declares the constant throws
  `missing Aiken constant <name>` (`golden-channel.mjs:185`).

**Stale when** lists what the table maps to the channel. Every channel is also
stale when its generator, one of its outputs, or (for workspace producers) any
`src/**` file of the producing package or its runtime workspace dependencies
changes. Those are not repeated per channel.

## TypeScript-to-Aiken golden channels

All generators here share `golden-channel.mjs`. `:check` builds the package, runs
the generator into a temporary copy, formats generated Aiken with `aiken fmt`
(the binary in `MIDGARD_AIKEN_BIN`, else `aiken` on `PATH`,
`golden-channel.mjs:81`), and fails on any difference. `:sync` writes the files.

Notes a reader needs:

- `transition-trace-abi` has two halves. The sync script
  (`fixtures:transition-trace-abi`) first re-emits the JSON through the SDK
  encoder in `tests/sdk-abi-fixtures.test.ts`, then renders the Aiken module.
  The `:check` is a pure JSON-to-Aiken comparison; the JSON half is held by
  `pnpm --dir demo/midgard-node test` [ci: Midgard Node CI/Test Midgard node].
  The check prints nothing when clean (measured 2026-09-25, exit 0 in 0.03 s).
- `validation-one-step-cross-language` syncs with
  `make validation-one-step-cross-language` (Makefile:59), which builds, writes
  the module, then runs the module's focused `aiken check`. Its generator's
  failure message points at that make target, which writes rather than checks.
- `lucid-native-fixtures` must be synced before `native-compact-aiken`; the
  script lists them in that order.
- `ordered-collection-boundary-aiken` and `nested-boundary-aiken` rerun vitest
  suites with `MIDGARD_WRITE_AIKEN_VECTOR` set, so their `:check` is heavy
  (minutes, not seconds).

Blind spots:

- `config/deployments/**` is in neither workflow's path filter
  (`.github/workflows/aiken-ci.yml:3-10`, `.github/workflows/midgard-node-ci.yml:3-42`).
  A pull request that changes only a profile YAML runs no profile check. Run
  `deployment:check` yourself [review].
- The witness-prefix step only runs for pushes to `main` and for pull requests
  that target `main` (`aiken-ci.yml:146`). On any other base it does not run.
- `deployment:generate <profile>` rewrites the `SELECTED_DEPLOYMENT_PROFILE`
  line (`demo/scripts/deployment-profiles.mjs:218`). The committed selection is
  `preprod-testing`. Generating another profile leaves a diff that looks like a
  profile change.
- `deployment:build` also regenerates, then asserts the pinned compiler and runs
  `aiken build --env <profile>` (`deployment-profiles.mjs:260-290`). It writes
  `plutus.json` and the gitignored `plutus.json.deployment.json`.
  [`config/deployments/README.md`](../../../../config/deployments/README.md) is
  the authority for profiles.

## Deliberately not channels

Listed under `ignored` in `channels.json`, each with its reason: the dist source
digest stamp (`demo/midgard-core/scripts/write-dist-source-digest.mjs`, writes
into the gitignored `dist/`), the devnet acceptance env writer
(`demo/midgard-node-tools/devnet/phase4-process/scripts/write-acceptance-env.sh`,

(writes a run artifact). The benchmark report scripts in
`onchain/aiken/scripts/` write to `benchmarks/output/`, which
`onchain/aiken/.gitignore` ignores, so discovery never sees them.
