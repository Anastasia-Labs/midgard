# What the pre-commit hook really does

Source: `.githooks/pre-commit` (read in full, as of 2026-09-25). Installed by
`bash .githooks/install` (or `pnpm --dir demo run hooks:install`), which
symlinks each hook into `$(git rev-parse --git-common-dir)/hooks` and keeps any
pre-existing real hook file as `<hook>.local`.

## In order

1. **Escape hatch.** `MIDGARD_SKIP_HOOKS=1` exits 0 immediately (line 34).
   Everything below is skipped, including the `pre-commit.local` shim.
2. **Nothing added, copied, modified or renamed is staged → exit 0** (lines
   44–47). A commit that only stages deletions runs nothing else, not even the
   shim.
3. **Blueprint refusal.** A staged `onchain/aiken/plutus.json` blocks the
   commit with instructions to `git restore --staged` it (lines 49–60).
4. **Partially staged files are reported and skipped.** A staged path that
   also has unstaged changes is not formatted: formatting it would stage the
   unstaged half too. The hook lists it ("partially staged — not formatted")
   and continues; the commit still goes through unformatted.
5. **TypeScript and Markdown under `demo/`** (`*.ts`, `*.tsx`, `*.md` at any
   depth): `demo/node_modules/.bin/prettier --write`, then
   `eslint --fix --max-warnings=0` on the `.ts`/`.tsx` subset, both run from
   `demo/`. Problems eslint cannot fix block the commit. A missing prettier or
   eslint prints a warning and **the commit proceeds unformatted/unlinted**.
6. **Aiken sources** (`*.ak` anywhere). The compiler is `MIDGARD_AIKEN_BIN`,
   else `aiken` on `PATH`.
   - An `aiken` exists but the checkout has no
     `onchain/aiken/scripts/pinned-compiler.mjs` to verify it with → blocked.
   - `node onchain/aiken/scripts/pinned-compiler.mjs <aiken>` fails (not the
     fork pinned by `AIKEN_FORK_VERSION` in the workflows) → blocked.
   - Otherwise `aiken fmt <files>`, then `sed -i 's/[[:space:]]\+$//'` on the
     same files: the formatter emits trailing spaces for monadic `let`/`expect`
     syntax, and CI strips them the same way before comparing. A parse failure
     blocks the commit.
   - No `aiken` binary at all → warning, **commit proceeds unformatted**.
7. **Re-stage** exactly the files it formatted (`git add -- <those paths>`).
8. **Chain to `pre-commit.local`** if `$repo_root/.git/hooks/pre-commit.local`
   is executable (line 168). This runs even when an earlier step failed.

Every "proceeds" above means the hook cannot be trusted to have formatted
anything; the CI format gates are the backstop
(`midgard-node-ci.yml` "Lint and format-check the demo workspace",
`aiken-ci.yml` "Run normalized Aiken auto-formatter check").

A bare `aiken fmt --check` is not the CI check: on 2026-09-25, 33 of the first
400 tracked `.ak` files differ from raw formatter output only by that
trailing-space artifact, so `--check` rejects files CI accepts.
`commit-paths` compares against the normalized output instead.

## The `pre-commit.local` shim

In the main checkout, `.git/hooks/pre-commit.local` (as of 2026-09-25) is a
shim generated by the pre-commit framework from the git-hooks.nix config
(`.pre-commit-config.yaml`, a gitignored symlink into the Nix store). Its
hooks are Haskell-only (`cabal-fmt`, `fourmolu`), but the framework stashes
before running them regardless of what is staged
(`pre_commit/commands/run.py`, `stash = not args.all_files and not args.files`): <!-- doc-links:external -->

1. `git diff-index --binary` of the worktree against the index tree is saved to
   a patch file.
2. `git checkout -- .` resets **every tracked file** in the tree to its index
   content.
3. The hooks run.
4. The patch is re-applied. If it conflicts with a hook's fix, the fixes are
   rolled back with another `git checkout -- .` and the patch applied again.

Consequences in a shared tree:

- A file another session writes between steps 2 and 4 can be overwritten or
  discarded by the re-apply or the rollback.
- Every tracked file with unstaged changes is rewritten on every such commit, so file
  mtimes show the time of the last commit, not the last edit. Do not infer
  that another session is active from mtimes.

## Where it does not run

- **Linked worktrees.** The hook looks for `$repo_root/.git/hooks/pre-commit.local`;
  in a linked worktree `.git` is a file, so the shim is never found. The
  Midgard hook itself still runs there, because the hooks directory is shared
  through the common git dir (and, on the maintainer machine as of
  2026-09-25, `core.hooksPath` is set to the main checkout's absolute
  `.git/hooks`).
- **`MIDGARD_SKIP_HOOKS=1`**, which also skips all formatting.
- **`commit-paths`**, which writes the commit with `git commit-tree` and runs
  no hooks.

`.agents/skills/committing-safely/scripts/commit-paths.test.mjs` ("git hooks") proves these three cases against
a copy of the real hook in a throwaway repository, with a control commit that
does reach the shim.
