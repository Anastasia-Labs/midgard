# Opening a PR

Read [the host adapter](../references/host-adapter.md) before host-dependent operations.

1. Confirm PR delivery is within the requested scope. Preserve dirty work and use a codex/ branch or isolated worktree when needed.

2. Read [committing-safely](../../committing-safely/SKILL.md) before committing and [writing-reports-and-prs](../../writing-reports-and-prs/SKILL.md) before writing the body. Run required and narrow checks on the final change.

3. Create or update the PR through available GitHub tools or gh. Use a temporary body file with --body-file for multiline CLI descriptions. Set the actual intended base and readiness; respect requested draft status.

4. Attach every created PR through the Codex app attachment tool when available. Confirm the current URL and head, then report checks and limits.

5. Opening a PR does not authorize merging or a standing babysit loop. Follow those workflows when the user requested them.
