\section{Transaction}
\label{h:transaction}

A canonical V1 transaction source set is a finite map from transaction ID to the
authenticated L2 transaction proof source.  The ID is the domain-separated Blake2b-256 hash of
the compact transaction body (defined below); equivalently, the map key must match the
\code{tx\_id} field in the source value.  The witness-set hash and field lengths
are authenticated by the block's \code{transactions\_root} through that value,
but they are not part of the transaction ID:
\begin{align*}
    \T{TxSetV1} &\coloneq \T{Map(TxId, L2TransactionSourceV1)} \\
      &\coloneq \Bigl\{
        (k_i: \T{TxId}, v_i: \T{L2TransactionSourceV1}) \mid
        k_i \equiv v_i.\T{tx\_id} ,\;
        \forall i \neq j.\; k_i \neq k_j
    \Bigr\}
\end{align*}

The exact source value is:
\begin{align*}
    \T{L2TransactionSourceV1} \coloneq \left\{
      \begin{array}{ll}
        \T{tx\_id} : & \T{TxId} \\
        \T{source} : & \T{NativeTxProofSourceV1}
      \end{array} \right\} \\
    \T{NativeTxProofSourceV1} \coloneq \left\{
      \begin{array}{ll}
        \T{compact\_cbor} : & \T{ByteArray} \\
        \T{witness\_set\_compact\_cbor} : & \T{ByteArray} \\
        \T{field\_preimage\_lengths\_cbor} : & \T{ByteArray}
      \end{array} \right\}
\end{align*}

The production V1 encoder derives a domain-separated commitment:
\begin{align*}
  \T{MidgardTxProofCommitmentV1} \coloneq {}& \mathcal{H}_{\T{Blake2b-256}}( \\
    & \T{"MidgardNativeTxProofSourceV1"} \\
    & \mathbin{\Vert} \T{Cbor(1)} \mathbin{\Vert} \T{Cbor(source)})
\end{align*}
The committed source value does not carry a copy of it.
The validation claim derives it from \T{NativeTxProofSourceV1} and compares it with the initial machine state's commitment.
The L1 transaction-order payload still carries \code{transaction\_commitment} and verifies the same derivation at authentication.
The former field-receipt chain is removed; current order material uses the shared field-carriage door described in \cref{h:transaction-order-event}.

The \code{transactions\_root} is the source root for normal L2 transaction requests.
Forced L1 transaction orders are committed separately in \code{forced\_transactions\_root}, keyed by their L1 order identity.
The normal root uses the \code{TransactionsV1RootDomain} counted-root domain,
while the forced root uses the distinct
\code{ForcedTransactionsV1RootDomain} domain.
Only accepted normal L2 transaction requests may appear in \code{transactions\_root}.
Invalid normal L2 transaction requests are excluded before commitment; they do not become no-op source events in the transition trace.
If two accepted normal L2 transactions share the same \code{TxId}, the block body is not canonical because \code{transactions\_root} is keyed by \code{TxId}; production block construction fails closed rather than choosing one silently.

An L2 transaction request in a Midgard block is an endogenous event.
Its corresponding utxo set transition is validated purely based on the information contained in the utxo set.
This contrasts with deposit and withdrawal events, which create and spend utxos (respectively) based on information observed outside the L2 ledger.

\paragraph{Canonical V1 consensus profile.}
The transaction structures below describe the canonical protocol-version (1),
native-transaction-version (1) surface. Canonical V1 enables public-key,
native-script, PlutusV3, and MidgardV1 authorization together with mint and
burn, reference inputs, script witnesses, redeemers, observers, reference
scripts, script payment credentials, and protected outputs. These features are
part of the normative V1 profile rather than dormant codec fields. Unknown
versions, languages, purposes, or encodings fail closed.

Canonical V1 has no independent (8{,}192)-byte whole-transaction ceiling.
Each canonical transaction aggregate preimage is bounded independently at
(32{,}768) bytes; the field-carriage rules and measured publication frontier are defined in \code{docs/spec/midgard-tx.md}, Section~8.
The profile's (4{,}095)-byte machine-chunk reservation is not the current field-publication chunk size. A ledger-output preimage is at most (16{,}384) bytes, and
the canonical CBOR encoding of an output value is at most (5{,}000) bytes.
Reference scripts are supported: a consensus program envelope is at most
(50) bytes and commits to at most (1{,}597{,}819) canonical CEK material
nodes and (67{,}108{,}417) structural material bytes, with blob chunks of at
most (4{,}095) bytes. Wrapping all independently bounded transaction
preimages in the canonical encoding gives the exact derived full-transaction
maximum of (295{,}041) bytes. None of these limits is operator-tunable policy.

Script-controlled spends and mint or burn are admitted only when the
corresponding scripts and policies authorize them. Their effects participate
in the mint-aware value-preservation equation in
\cref{h:custom-midgard-ledger-rules}.

\subsection{Deviations from the Cardano transaction types}
\label{h:deviations-from-cardano-transaction-types}

Midgard's transaction types deviate from Cardano's in the following ways:
\begin{description}
    \item[No staking or governance actions.] Midgard's consensus protocol is not based on Ouroboros proof-of-stake, and its governance protocol is not based on Cardano's hard-fork-combinator update mechanism.
      Furthermore, Midgard's L1 scripts cannot authorize arbitrary staking or governance actions on behalf of users.
      For this reason, staking and governance actions are prohibited in Midgard L2 transactions.
    \item[No pre-Conway features.] Midgard does not need to maintain backwards compatibility with pre-Conway eras.
      Midgard deposits and transactions will be prohibited from using bootstrap addresses, and Shelley addresses with Plutus versions older than Plutus V3.
      Canonical V1 admits public-key and native-script credentials together
      with PlutusV3 and MidgardV1 programs and script payment credentials;
      unknown or pre-Conway language versions fail closed.
    \item[No transaction metadata.] Midgard prohibits metadata in L2
      transactions. Canonical V1 therefore requires
      \code{auxiliary\_data\_hash} to equal the empty-null root; a non-empty
      hash fails closed because no authenticated auxiliary-data preimage is
      carried by the transaction.
    \item[No datum hashes in outputs.] Midgard output datums are either absent or inline.
      Datum-hash outputs are invalid in Midgard L2 transactions and deposits, and transactions do not carry a datum-witness bucket.
      This avoids maintaining a datum-hash to datum witness map and makes each UTxO's script-visible datum fully determined by the UTxO itself.
    \item[Observer purpose and authored input order.] Midgard's design draws on \href{https://github.com/cardano-foundation/CIPs/tree/master/CIP-0112}{CIP-112} and \href{https://github.com/cardano-foundation/CIPs/tree/master/CIP-0128}{CIP-128}.
      The canonical profile defines the admitted observer and input-order semantics directly; these references do not assert current Cardano activation or that every feature of either proposal is implemented.
    \item[Different network ID.] Midgard transactions and utxo addresses use a different network ID to distinguish them from their Cardano mainnet counterparts.
      The current canonical mint format carries 28-byte policy IDs without a new L1/L2 origin prefix.
    \item[Time domains require reconciliation.] The original design uses POSIX timestamps in L2 transaction intervals, while block event intervals are also expressed as POSIX times.
      Current \code{validation-machine/shared.ak} compares native transaction interval scalars directly with \code{block\_slot}, and the node derives that slot with its L1 slot conversion.
      Transaction-order due checks also compare the interval with block event times.
      These boundaries require one explicit, consistent unit contract and conformance evidence; this draft does not silently convert the POSIX design requirement into a slot-based one.
    \item[Native validity and forced verdict.] User admission and normal block leaves require native validity code zero.
      The compact format admits codes zero and one; a forced leaf additionally carries a typed \code{OperatorVerdictV1}, and its compact code must agree with that verdict.
      This is distinct from Cardano's L1 phase-two \code{is\_valid} flag.
\end{description}

\subsection{Midgard-native transaction types and wire format}
\label{h:midgard-simplified-transaction-types}
\label{h:midgard-transaction-types}
\label{h:midgard-native-transaction-wire-format}

The canonical format authority is \code{docs/spec/midgard-tx.md}, Sections~2--6.
The Aiken encoders in \code{midgard/fraud-proofs/native-tx} and the TypeScript encoders in \code{midgard-core/src/codec} must agree byte for byte.
The former Cardano-shaped simplified records and receipt-based full-body projections are not alternative accepted encodings.

A native transaction has a version, a body, a witness set, and a validity code.
Its compact encoding is the four-element CBOR array
\begin{equation*}
  \T{NativeTxCompact} =
  [1,\; \T{NativeTxBodyCompact},\; \T{witness\_set\_hash},\; \T{validity\_code}].
\end{equation*}
The body is embedded as a twelve-element array, not replaced by its hash:
\begin{equation*}
\small
\begin{split}
\T{NativeTxBodyCompact} = [&
\T{spend\_inputs\_hash},\;
\T{reference\_inputs\_hash},\;
\T{outputs\_hash},\;
\T{fee},\\
&\T{validity\_interval\_start},\;
\T{validity\_interval\_end},\\
&\T{required\_observers\_hash},\;
\T{required\_signers\_hash},\;
\T{mint\_hash},\\
&\T{script\_integrity\_hash},\;
\T{auxiliary\_data\_hash},\;
\T{network\_id}].
\end{split}
\end{equation*}
An unbounded interval side uses the integer sentinel \code{-1}.
The witness compact is the ordered triple of address-witness, script-witness, and redeemer-witness field hashes.
Its canonical CBOR bytes are hashed with Blake2b-256 to obtain \code{witness\_set\_hash}.

Transaction identity binds the compact body, including the native domain and version:
\begin{equation*}
\begin{split}
\T{TxId}=\mathcal{H}_{\T{Blake2b-256}}(&
\T{"MidgardNativeTxBodyV1"}\\
&\Vert\T{Cbor(1)}\Vert\T{Cbor(NativeTxBodyCompact)}).
\end{split}
\end{equation*}
The ASCII domain bytes are not themselves CBOR-wrapped.
Signatures bind this transaction ID.
The full-transaction and proof-source commitments use their own distinct domains and authenticate additional material; neither replaces the transaction ID.

Each of the nine variable-field commitments is the plain Blake2b-256 hash of its canonical field preimage.
A field preimage is a definite-length array of byte-string-wrapped canonical items; the empty preimage is exactly the byte \code{80}.
Field identity comes from the compact slot, not a field-index hash prefix.
Inputs and reference inputs use fixed-width 16-bit output indexes; variable-width items use their specified canonical encoders.
All length, envelope, value, script and nested Plutus-Data rules remain mandatory.

The full transaction carries actual native body and witness structures with their preimages, not an alternating list of redundant roots and preimages.
It has three witness collections: address witnesses, versioned script witnesses, and redeemer witnesses.
Non-native executable program material is carried and authenticated separately through its program-envelope commitments.
The exact full encoder, item grammar and three-tier carriage protocol are defined by the component specification rather than duplicated here.
