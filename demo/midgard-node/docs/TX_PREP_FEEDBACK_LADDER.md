# Transaction Preparation Feedback Ladder

Live preprod e2e is the final acceptance surface, not the first place to debug
deterministic transaction construction. For changes that touch builders,
transaction assembly, command orchestration, worker submission, wallet/input
selection, reference scripts, validity windows, or post-submit recovery, run the
lowest relevant layers first and record them in the e2e evidence.

## Layers

| Layer                       | Purpose                                                                                                                                                                                | Command                                          |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 0: pure SDK/native builders | Datum, redeemer, layout, validity, ordering, and local builder invariants without node IO.                                                                                             | `cd demo && pnpm run test:tx-prep:sdk`           |
| 1: node boundary            | CLI/worker orchestration, wallet switching, provider classification, reference-script resolution, timing gates, DA gates, and recovery behavior with fake providers or local fixtures. | `cd demo && pnpm run test:tx-prep:node`          |
| 2: targeted emulator        | Small validator-facing flows with real transaction completion and local UPLC evaluation.                                                                                               | `cd demo && pnpm run test:tx-prep:emulator`      |
| 3: local composed workflow  | Multiple local/emulator phases that prove a narrow cross-module path without preprod provider state.                                                                                   | `cd demo && pnpm run test:tx-prep:local`         |
| 4: live acceptance          | Provider compatibility, preprod timing, copied DA node integration, DA attestation, merge/finality, DB health, and final evidence.                                                     | `.agents/skills/midgard-e2e-acceptance/SKILL.md` |

## Policy

- Builder-only changes must pass the relevant Layer 0 suite.
- Node transaction-preparation changes must pass Layer 1 and the smallest Layer 2 emulator proof for the affected flow.
- Commit, scheduler, DA, and merge changes must pass the focused worker/DA gates before live acceptance.
- A live e2e failure that reveals a deterministic builder/preparation defect is not closed by repeated live reruns. Add a targeted local or emulator regression, fix it, then return to live acceptance.
- Do not weaken local UPLC evaluation, script checks, reference-script identity, wallet-role separation, DA threshold, or state-reset rules to make a lower layer pass.
