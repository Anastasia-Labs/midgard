## Notes

- Shared infrastructure this chunk's verdicts depend on: `tests/helpers.ts` (`makePayloadFixture` derives every header root from `computeDaPayloadRoots` and hashes the header with the production `hashBlockHeader`, so the fixture is derived rather than transcribed -- this is why most files score well) and `tests/helpers/deployment-fixture.ts` (derives every scriptHash via `validatorToScriptHash`, builds the fraud-proof catalogue trie with the real MPF library, and recomputes `manifestId` with `computeDeploymentManifestId`). Neither carries hand-maintained digests; there are no `*fit-ledger`-style self-comparing pins anywhere in this chunk.
- `minimalConfig` in helpers.ts sets several fields to production constants (`LIBP2P_DA_TRANSPORT_LIMITS`, `LIBP2P_DA_MIN_RETENTION_DAYS`, `MIDGARD_CONSENSUS_PROFILE`). config.test.ts builds its manifest fixture from those same constants and then asserts the loaded config equals them (L152-153), so that pairing is a pure round trip and cannot catch a wrong constant value. The retention-days value is independently anchored in store-retention.test.ts L520-522 against `MIDGARD_RETENTION_WINDOW.retentionDays`, and the retention window arithmetic is pinned to literal ms values (L395-398), so the constant itself is covered elsewhere.
- Production paths actually exercised: real `JsonFileWatcherStore` on real temp directories with genuine close/reopen restarts (watcher, conflict-evidence, store-retention, libp2p-proof-protocols); real Lucid `Emulator` (availability-responder-factory, scalus-add-signatures-eval); the real Plutus validator under the Scalus UPLC evaluator in exactly one file (scalus-add-signatures-eval.test.ts) -- that is the only place a wrong bitmap, witness ordering or signed message is caught by on-chain code, and it has no rejection counterpart. No test in this chunk touches a real Postgres, a real libp2p swarm, or a real Cardano node; Kupo/Ogmios and libp2p are modeled by hand-written doubles (provider.test.ts, state-queue-replay-provider.test.ts, public-retained-da-store.test.ts, libp2p-proof-protocols.test.ts).
- Weakest file by a clear margin is `public-retained-da-store.test.ts`: it makes a persistence/privilege claim (the public plane is structurally incapable of deleting challengeable evidence) that a mock-only test cannot establish, and one of its cases asserts behaviour the double itself implements. Its refusal cases over the privilege-probe decision are genuine, so the fix is to add a real-Postgres conformance test for the `pg_roles` probe SQL rather than to delete the file.
- Only one skip in the chunk: watcher.test.ts L1671 `it.skip`, preceded by an explicit cause and re-enable condition (issue 646, both polarities deliberately unpinned). Compliant with the owner ruling. state-queue-scanner.test.ts L141-145 similarly records a removed adversarial case against issue 645.
- Discoverability risk (rubric 14): `cardano-capability-retained-da-corpus.test.ts` drives `describe.each(corpus.entries)` from a JSON fixture in another package (`../../midgard-fault-proofs/tests/fixtures/cardano-capability-p2-boundary-corpus-v1.json`) with no assertion that the corpus is non-empty, so an empty or truncated corpus would report a green run with zero cases. It also honours `MIDGARD_BOUNDARY_CORPUS_JSON` to repoint the corpus at an arbitrary absolute path -- fine for regeneration workflows, but it means the required run's input is environment-dependent.
- CI: `da-committee-node`'s package `test` script runs in `.github/workflows/midgard-node-ci.yml`, so every file here executes in CI, and the package sets `restoreMocks: true`. No file in this chunk is env-gated or opt-in. `scripts/check-no-http-da-transport.mjs` is reached only through `no-http-da-transport.test.ts` (vitest), not as a separate CI step -- adequate, but the guardrail dies silently if that one test is ever skipped.
- Review-gate answerability: every file except `runtime-capability.test.ts` and `public-retained-da-store.test.ts` gives a reviewer a clear Contract/Failure-mode/Oracle/Execution answer. For those two, "Oracle" (a manifest string compared to itself; a fake that implements the rule it is asked to prove) is the unanswerable column.
- Readability debt, not scored: watcher.test.ts repeats the same ~35-line signer/config/validation preamble in roughly fifteen tests, and tx-builders.test.ts / submitter.test.ts each carry near-identical copies of the `DaAttestationValidatorSet` fixture builders. Consolidating those would not change any file's protection.
