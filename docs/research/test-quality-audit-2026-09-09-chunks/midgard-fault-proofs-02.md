## Notes

- **Fit-ledger family (5 files in this chunk).** Two distinct templates. The *builder* template (`transaction-output-non-canonical-fit-ledger`, `protected-output-signer-missing-fit-ledger`) transcribes the whole measurement table plus the blueprint digest into the test, calls `buildVanRossemFitLedger`, and compares the result to the stored JSON. Its margin assertions are dead code: `entryFromMeasurement` in `src/proof-fit/van-rossem-fit-ledger.ts` (L80-89) throws before any non-positive margin can reach an `expect`. The *reader* template (`field-item-width-illegal-fit-ledger`, `resolved-output-non-canonical-fit-ledger`) reads the JSON and re-derives margins from the exported limits, which is better but still pins a hand-transcribed `PINNED_BLUEPRINT_SHA256` and a hand-maintained row-name list. `execution-source-script-decoding-fit-ledger.test.ts` (outside this chunk, read for calibration) is the correct template: it sha256s `realBlueprintPath` at test time and rebuilds the ledger from the stored entries. All four should move to that shape. `resolved-output-non-canonical` additionally carries two checks worth keeping regardless: the 80%-of-limit proof-fit reserve and the `ledgerSha256` recomputation.
- **The real fit oracle is the lifecycle suite, not the ledger test.** `transaction-output-non-canonical-lifecycle.test.ts` records every measurement itself and asserts `l1ByteMargin > 0` per transaction (L102, L1297-1299); the same pattern appears in `value-conservation-lifecycle` and `distinct-asset-accumulation-limit-lifecycle` via `expectProofFit` against the emulator's own protocol parameters. Those gates run on real measurements, so the ledger tests add no independent protection — only churn.
- **Real production path.** Ten of the nineteen files run the real compiled Aiken validators on a Lucid emulator with `localUPLCEval`, driven by the production submitters (`makeFaultProofEmulatorHarness` / `makeDecodingEmulatorHarness` / `makeValueNotPreservedEmulatorHarness`). Nothing in this chunk uses a stubbed validator or evaluator. The small pure files (`predecessor-replay`, `input-no-idx`, `execution-native-script-invalid-canonical-reconstruction`, `network-id-wrongful-rejection`) call real production modules against `tests/helpers/canonical-block-evidence-fixture.ts`, which builds its roots with the production encoders and `buildCountedRoot` — the fixture does not hide the decision.
- **`expectOnchainRefusal` (`tests/support/emulator/expect-onchain-refusal.ts`) is the chunk's most load-bearing helper** and it is correct: it requires the failure text to match `/failed script execution/`, so an off-chain builder throw cannot satisfy an on-chain negative. Every file that uses it (`native-script-decoding-adversarial`, `transaction-output-non-canonical-lifecycle`) is materially stronger for it. By contrast `value-conservation-lifecycle` (L1085, L1160) and `distinct-asset-accumulation-limit-lifecycle` (L1078, L1154, L1195) use bare `.rejects.toThrow()` with no message or class — those arms are `negative-uncontrolled` and should route through the same helper or name the refusal.
- **`native-script-decoding-adversarial` is the model for negatives in this repo.** Every on-chain refusal is followed by a control transaction differing only in the targeted condition, and where a control varies two things at once the file says so explicitly (L899-909) rather than overclaiming.
- **CI.** `midgard-fault-proofs`'s package `test` script runs in `.github/workflows/midgard-node-ci.yml`, so every file here except `resolver-proof-fit-sweep-generate.test.ts` executes. That one is `describe.skipIf(!MIDGARD_REGENERATE_RESOLVER_SWEEP)` and is only ever invoked by `demo/midgard-validation/scripts/generate-resolver-proof-fit-sweep-v1.mjs`; it is a generator misfiled as a test and provides no ongoing protection.
- **Test interdependence, fail-closed.** `transaction-output-non-canonical-lifecycle.test.ts`'s fourth `it` (L1276) asserts coverage accumulated by the three preceding tests in the same file. This violates the independence rule mechanically, but `assertCompleteLifecycleCoverage` fails closed on an empty snapshot, so a filtered run cannot pass vacuously. Worth noting rather than fixing.
- **Env-gated writers, not env-gated coverage.** `MIDGARD_WRITE_FIT_LEDGER`, `MIDGARD_PRINT_FIT`, `MIDGARD_PRINT_PROOF_FIT` and `MIDGARD_FIT_OUT` only gate artifact writing and console output; the assertions run unconditionally. These are not `env-gated` in the coverage-impersonating sense.
- **Could not determine:** whether the Aiken-side constants transcribed into `fabricated-withdrawal.test.ts` (L102-157) are machine-checked against the Aiken fixtures anywhere. The file's header says they were measured out of `onchain/aiken/lib/midgard/fraud-proofs/fabricated-withdrawal/step-0{1,2,3,4}.ak` and are also pinned in `demo/midgard-sdk/tests/fabricated-withdrawal.test.ts`, which is a genuine cross-implementation vector, but I did not open the Aiken modules to confirm the values still match. If they drift, both TypeScript copies drift together silently.
