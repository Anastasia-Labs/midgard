## Notes

- **Production path.** All 34 files exercise real Midgard `src/` code; no file in this chunk stubs the decision it claims except `script-integrity-hash-mismatch-manifest-workflow.test.ts` (every collaborator vi.mock'ed). The `*-lifecycle.test.ts` and `submit-init-emulator-*.test.ts` families run the Lucid Emulator with the REAL compiled Aiken validators loaded from `onchain/aiken/plutus.json` (or `MIDGARD_REAL_BLUEPRINT_PATH`) and local UPLC evaluation; refusals are genuine script failures.
- **Shared helpers this chunk's verdicts depend on, all sound.** `tests/support/emulator/blueprints.ts` refuses to deploy a validator whose declared parameter arity does not match what is applied (#610) - this is what stops an under-applied always-succeeds script from making these suites unfalsifiable. `tests/support/emulator/expect-onchain-refusal.ts` requires the message to contain "failed script execution", so an off-chain builder guard or fixture error cannot satisfy an on-chain refusal claim; `field-preimage-length-mismatch-lifecycle.test.ts` L137-158 defines its own stricter variant that additionally asserts the message is NOT one of the family's own guards. `tests/support/emulator/proof-fit.ts` asserts a real derived acceptance criterion (>=0 byte margin, 20% execution reserve). `tests/support/emulator/dispute-scenario.ts` is the shared 1,570-line real-emulator lifecycle driver behind all the validation-dispute files.
- **Two oracle templates coexist for fit ledgers.** The GOOD template (`unused-script-witness-lifecycle.test.ts` L1535-1590, `validation-trace-resolver-publication.test.ts` L100-103) hashes the real blueprint at test time and builds the ledger from measurements taken in the same run, then asserts derived margins. The BAD template is `observer-order-invalid-fit-ledger.test.ts`: it reads a committed JSON, compares its `blueprintSha256` to a hand-transcribed constant (L26-27), and re-checks margin arithmetic against the same JSON's own fields - a saved measurement re-read, not a new one. That file is the only D-or-below oracle in the chunk on this axis.
- **Env-gated measurement blocks.** The four `submit-init-emulator-validation-dispute-script-sources-*.test.ts` files and `ledger-output-proof-publication.test.ts` put their execution-unit ceilings, the `expect(completed).toBe(N)` scenario-count gate, and the ledger write inside `afterAll`/`if (process.env.MIDGARD_WRITE_FIT_LEDGER === "1")`. In ordinary CI those assertions never run - the lifecycle `it` bodies still do, so the files are not empty, but the fit numbers are not gated by default. `tests/support/measured-fit-ledger.ts` has the same gate.
- **Template families with duplicated coverage.** (a) `spend-input-signer-missing-`, `protected-output-signer-missing-`, `resolved-output-non-canonical-authenticated-workflow.test.ts` are three near-identical copies (same three tests, same hand-copied manifest lists, same near-tautological accept path) - one parameterized suite would lose nothing. (b) The four `script-sources-{discovery,middle,observer,observer-max}` files share an identical 57-line measurement wrapper and the same three-way polarity shape; only the slot sets and carriage maxima differ.
- **Coarse negative matchers.** The script-sources dispute files assert `rejects.toThrow(/semantic-resolution/)` - that is the lifecycle STAGE LABEL, so any failure inside the semantic-resolution stage satisfies it. Causality is nonetheless established by construction (the paired positive uses the identical fixture with only `dishonestChallenger` flipped), but a fixture/plumbing break in that stage would read as a successful refusal. Same pattern with bare `rejects.toThrow()` at execution-native-script-invalid-lifecycle L1210/1225/1240.
- **File-scoped shared state.** `field-preimage-length-mismatch-lifecycle.test.ts` and `unused-script-witness-lifecycle.test.ts` accumulate coverage/measurements across tests in the file and assert completeness in a final `it`. This is a genuine coverage gate but it fails spuriously if the file is run with a `-t` name filter or a single test is skipped.
- **CI.** `demo/midgard-fault-proofs` package `test` runs in `.github/workflows/midgard-node-ci.yml`, so every file here executes (fault-proofs vitest: isolated forks, maxForks 8). Fail-closed on a missing blueprint: `readBlueprint` throws if `onchain/aiken/plutus.json` is absent, so a missing build cannot silently pass. I did NOT verify that the CI job actually builds that blueprint before running the suite - that is the one open CI question for this chunk.
- **Could not determine.** Whether the pinned `PINNED_BLUEPRINT_SHA256` in `observer-order-invalid-fit-ledger.test.ts` currently matches the blueprint the rest of the chunk measures against (the blueprint is gitignored/build-produced, and the audit is read-only with no build permitted). If it is stale the file is failing rather than merely weak; if it matches, it is churn as graded.
