## Notes

- **Two template families in this chunk.** (a) Emulator lifecycle files (`submit-init-emulator-*`, `*-lifecycle`, `*-adversarial`) build real state-queue blocks, apply the real compiled Aiken validators, evaluate UPLC locally, sign and submit; refusals route through `tests/support/emulator/expect-onchain-refusal.ts`, which requires the failure text to match `/failed script execution/` -- so they are causally controlled negatives, not "something failed". These are consistently the strongest files here (scores 9-10). (b) Pure planner/codec/evidence files, which are mostly good but lean on transcribed production constants in a few places.
- **Shared helpers this chunk's verdicts depend on** (all read and checked): `tests/support/emulator/expect-onchain-refusal.ts` (genuine causal gate); `tests/helpers/canonical-block-evidence-fixture.ts` (real payload envelope + authenticated header observation); `tests/support/measured-fit-ledger.ts`; `src/testing/complete-lifecycle.ts` (the coverage gate -- it reports every omission and is fed by a recorder populated during the run, never pre-filled); `tests/support/route-freedom-journey.ts`.
- **Fit-ledger pattern is healthy in this chunk.** `verifyMeasuredFitLedger` derives `blueprintSha256` from the real blueprint file and compares it to the checked-in ledger -- the correct template, not the self-comparison antipattern the earlier audit found in `*fit-ledger.test.ts`. No self-comparing digest pin exists in any file in this chunk. The residual cost is churn: any blueprint rebuild invalidates a checked-in ledger. Note `witness-script-decoding-lifecycle.test.ts` avoids even that by building the ledger at test time and asserting positive margins.
- **Env-gated assertions that never run in CI (the chunk's main CI gap).** `submit-init-emulator-validation-dispute-phase-a-item.test.ts` L59 returns from `afterAll` unless `MIDGARD_WRITE_FIT_LEDGER=1`, so its only real acceptance criteria (13.2M memory / 8G CPU unit ceilings, L76-79) and its `expect(completed).toBe(6)` completeness check never execute; the same env gate covers `cek-selection-yield-lifecycle.test.ts` and `tests/support/measured-fit-ledger.ts`. The `completed` count also looks stale (the phase-A file invokes the scenario ~10 times).
- **Blueprint-gated skips.** Both route-freedom files use `describe.skipIf(!realBlueprintSpeaksOptionBV1())`. The cause and re-enable condition are documented (`OPTION_B_SKIP_REASON`), which satisfies the skip rule, but the file still goes green rather than red when the blueprint predates Option B -- an impersonated-coverage risk for two whole journeys.
- **Transcribed production constants (the chunk's recurring weakness).** `workflow-runtime.test.ts` L1101-1156 (all 54 runner-factory keys), `transaction-output-non-canonical-workflow.test.ts` L62-72 (manifest contract list) and `validation-proof-item-delivery-route.test.ts` L24-31 (the envelope measurement re-typed as a literal). The sibling route-freedom files show the fix: read the constant from `MIDGARD_ENVELOPE_MEASUREMENTS`. Spec identifiers pinned as hex category ids (`00000006`, `00000011`, `00000013`, `00000026`) are legitimate external identifiers, not churn.
- **One mock-only file.** `historical-native-script-preimage.test.ts` replaces both authority modules with `vi.mock` doubles that implement the admission themselves, so the module's central claim ("two independent authority paths agree") is never exercised; two of its assertions verify the mock's own WeakSet. It is the only D in the chunk.
- **Weak-assert cluster in the validation-dispute lifecycles.** `cek-selection-yield-lifecycle.test.ts` and `submit-init-emulator-validation-dispute-phase-a-item.test.ts` run 900s/180s real emulator journeys but assert only `txHash.toHaveLength(64)` and `removal.transactions.length > 0`. The emulator run itself is meaningful evidence (a validator refusal would throw), but the visible oracle is far weaker than the sibling families' (compare `submit-init-emulator-withdrawn-reference-input-lifecycle.test.ts`, which pins the removed operator, the emptied state-queue root and the scheduler state).
- **One vacuous-sweep risk.** `wave0-shared-substrate.test.ts` L98-114 resolves its scan roots from `process.cwd()`; an empty file list passes silently.
- **No duplicated coverage found.** `submit-init-emulator-missing-native-script-tx-tier2` and `submit-init-emulator-native-script-decoding-tier2` share the same 14,603-byte tier-2 premise but drive different families through different §8.8 doors.
