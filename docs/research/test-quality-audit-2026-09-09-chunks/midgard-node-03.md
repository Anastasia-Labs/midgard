## Notes

- **Template families.** Three files share one "exact V1 envelope" parser-rejection template: `pending-finalization.test.ts`, `foreign-tip-reconciliation.test.ts`, and (for its evidence decoders) `phas-membership-registration.test.ts`. All build one valid baseline and mutate a single field per case -- causally controlled and good -- but nearly every rejection asserts a bare `.toThrow()` with no error category, so an over-strict parser that refuses the valid shape for the wrong reason still passes each reject case (the paired accept case is what saves them). Adding the refusal code/message to these tables is the cheapest strengthening in the chunk.
- **Shared helpers the verdicts depend on.** `tests/helpers/availability-challenge-emulator.ts` -- its `assertAvailabilityRefusal` (L1270-1279) requires a UPLC evaluation failure (`/(?:Error evaluated at |Builtin error: )[^\n]*spent budget:/`), not any thrown error, so the ~10 refusal assertions in `availability-challenge-lifecycle.test.ts` are genuine validator refusals rather than uncontrolled negatives. `tests/helpers/real-midgard-contracts.ts` and `mainnet-protocol-parameters.ts` back the CG1 fit driver. `tests/helpers/transition-fixtures.js` and `midgard-output-helpers.ts` are mechanical.
- **Production paths actually exercised.** Real emulator ledger + real validators: `availability-challenge-lifecycle`, `scratch-cg1-publication-fit`. Real libp2p over loopback TCP with three real committee nodes and real file stores: `da-multi-peer-integration`. Real Node HTTP server: `listen-admission-auth`. Real Level/MPF on disk: `speculative-mpf-lifecycle` (last case), `commit-block-header-worker-output` (root-transaction case), `confirmed-ledger-snapshot`, `forced-transactions-root`, `transition-roots`. Real child-process script runs: `mpf-architecture-g-candidate-input`. Pure functions: `merge-readiness`, `startup-policy`, `merge-error-codes`, `state-queue-topology`, `mpf-architecture-g-corpus`, the validator/summary files. **No test in this chunk touches real Postgres** -- every DB-shaped claim (`state-queue-mutation-lease-endpoint`, `merge-maturity-preflight`, `migration-runner`) runs against a fake store or against the migration SQL as a string, despite the node vitest config provisioning per-worker Postgres shards. That is the chunk's largest execution gap.
- **CI gaps.** `scripts/mpf-architecture-g-candidate-summary.test.mjs` is referenced by no workflow and no package test script (per ci-summary.txt) -- 16+ mutation cases of the Architecture-G gate validator that never run. `scratch-cg1-publication-fit.test.ts` uses `describe.skipIf(!blueprintPresent)` and `onchain/aiken/plutus.json` is gitignored, so on a clean CI checkout the whole CG1 fit measurement silently skips; the skip is documented and honest, but it means the "every control validator fits 16,384 bytes" gate has no enforced execution point.
- **ci-summary correction.** `tests/phase4-pipelined-report.test.mjs` is listed there as a `node:test` file whose collection under vitest is doubtful. It is not -- it imports `describe/expect/it` from `vitest` (L6) and runs normally in the midgard-node vitest suite. The concern stands for the other three `.mjs` files named in that line, which I did not audit here.
- **Duplicated coverage.** `merge-maturity-builder.test.ts` and `merge-maturity-preflight.test.ts` both assert "DA/maturity is decided before the expensive step", at the builder and at the fiber respectively; the boundaries differ so both earn their place, but `merge-readiness.test.ts` already pins the same classification pure-function, so the two mock-heavy files exist only for the ordering claim. `da-attestation-config.test.ts` L291-300 ("still refuses a pre-Q63 threshold of one") repeats L265-274 exactly -- same config, same assertions; only the comment differs.
- **Could not determine.** Whether `resolveValidationWorkerPoolSize(undefined, 8) === 6` (validation-parallelization L185) encodes a reviewed policy or the current formula -- I did not open `src/services/config.ts` to check whether 6 is derived; if it is `cpus - 2` the assertion is a hand-transcribed instance of the formula rather than a contract.
