## Notes

- **Production paths exercised.** All but four files run a real Lucid emulator with the real Aiken blueprint (`onchain/aiken/plutus.json`, built in CI by `midgard-node-ci.yml` with the pinned Anastasia fork `aiken v1.1.23+5adf783`), real submitters and real removal. `missing-script-source-retained-universe` additionally uses `@lucid-evolution/scalus-uplc` as the evaluator. The pure-function files are `aiken-blueprint-data`, `prepare-input-no-idx`, `workflow-raw-l1-family-derivation`, `network-id-forced-workflow` (hand-rolled Lucid fake for UTxO queries only — a legitimate data-source injection, the decisions all run), the two fit-ledger files (file I/O only) and `native-script-decoding-envelope` (Data.to byte measurement, no evaluation). Only `script-integrity-hash-mismatch-replay` replaces the decision it claims to test with `vi.mock`.
- **Fit-ledger family.** `cross-block-workflow-fit-ledger` and `distinct-asset-accumulation-limit-fit-ledger` are *not* the tautological variant the earlier audit found: both derive the blueprint digest with `createHash('sha256')` over `realBlueprintPath` and compare it to the JSON, which is the correct template. Their remaining defect is different: the entries they feed back into `buildVanRossemFitLedger` were produced by that same builder, so the margin arithmetic is self-compared, and the measurements are historical rather than re-executed. A real producer already exists — `tests/support/measured-fit-ledger.ts` (`createMeasuredFitRecorder` / `verifyMeasuredFitLedger`) regenerates ledgers from freshly evaluated emulator submissions under `MIDGARD_WRITE_FIT_LEDGER=1` — so a `--check` CI job is the by-construction replacement for both. Four other files in this chunk (`missing-signature-*`, `native-script-invalid-*`, `mint-authorization-installed-*`, `submit-init-emulator-transition-trace-final`) contain the same env-gated `afterAll` writer; those blocks are inert in a normal run and are not coverage.
- **Shared helpers the chunk's verdicts depend on.** `tests/support/emulator/proof-fit.ts::expectProofFit` is a genuine derived gate (byte margin against the real 16,384 `maxTxSize` plus a 20% execution reserve computed from the emulator's own protocol parameters) — files that call it have a real acceptance criterion; `unused-redeemer-lifecycle` and `mint-authorization-installed-lifecycle` do not call it and only assert `> 0`. `tests/support/emulator/expect-onchain-refusal.ts` does verify the failure text matches `/failed script execution/`, so `double-withdraw`'s `.not.toBe("")` is backed by a real on-chain-refusal check. `tests/support/emulator/blueprints.ts` documents that it never rebuilds the blueprint and fails closed if it is absent.
- **Test-only bypasses.** `native-script-invalid-wrongful-rejection-lifecycle` and `unused-redeemer` pass `unsafeSkipLocalViolationCheckForTest` into production submitters, and `catalogue-retained-classification` / `mint-authorization-installed-lifecycle` call `unsafeCreate*ForTest` factories. These are explicit parameters used to make the *on-chain* check decisive rather than to weaken it (§6's concern is production silently taking an easier route, which is not what happens here), but they are production surface that only tests use and are worth reviewing as a group.
- **Generic refusal messages are the chunk's most common weakness.** `/failed script execution/`, `/failed|Validation|Script|script/i` and bare `rejects.toThrow()` appear across the emulator lifecycles. Where a positive journey and a targeted mutation share the same builder path the causality argument is reasonable, but none of these pin *which* on-chain clause refused, so a validator that started refusing for an unrelated reason would still pass.
- **CI.** `midgard-node-ci.yml` line 286 runs `pnpm --dir demo/midgard-fault-proofs test` (vitest run) after `aiken build --env testnet`, so every file here executes in CI; the fault-proofs vitest config uses isolated forks with `maxForks: 8`. `catalogue-retained-classification` hardcodes `mkdtempSync("/var/tmp/...")`, which is Linux-only (fine for CI, fails on other hosts).
- **Could not determine.** The provenance of the literal `expectedDual` in `script-integrity-hash-mismatch-replay.test.ts` (L17-18) — nothing in `src/script-integrity-hash-mismatch/` derives or documents it, so a reviewer cannot answer the Oracle question for that file. Likewise the four transcribed digests in `submit-init-emulator-fabricated-deposit.test.ts` (L81-88) have no in-repo derivation script; they are almost certainly hashes over the adjacent hand-written CBOR constants, but that is inferred, not shown.
