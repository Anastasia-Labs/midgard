## Notes

- **Shared harness family.** Five emulator files (`complete-item-route-adversarial`, `complete-item-carriage-tiers`, `complete-item-proof-fit`, `native-script-scan-fault-proof-exunits`, and to a lesser extent `field-preimage-carriage-fit`) share a near-identical private harness: a `submitStage` that wraps `tx.complete({localUPLCEval:true})`, `sameDatumValue`, `publishReferenceScript`, `feeInputFor`, and the seeded computation-thread token. Each keeps its own copy. The refusal idiom they all share — `rejects.toThrow(/local evaluation failed/)` — is that wrapper's own message, so a refusal caused by fee selection, index resolution or a builder bug is indistinguishable from a validator refusal. The red-then-green pairing in each file is what currently carries the attribution; a shared helper that surfaced the validator's own error string would make these refusals discriminating rather than merely paired.
- **Thread authenticity is out of scope everywhere.** All five emulator files seed the computation-thread token into the genesis account rather than minting it under the real policy, and say so. Nothing in this chunk establishes thread authenticity; that is delegated to the fault-proofs lifecycle suites (not in this chunk).
- **Blueprint dependency.** `complete-item-route-adversarial`, `complete-item-carriage-tiers`, `complete-item-proof-fit` and `native-script-scan-fault-proof-exunits` read `onchain/aiken/plutus.json`, which is gitignored and generated. The scan-bench file loads it lazily precisely so a missing blueprint skips rather than errors at collection; the other three read it at module scope and will throw during collection on any tree that has not built the blueprint. Whether the midgard-validation CI job builds the blueprint before `vitest run` could not be determined from the CI summary — if it does not, three of the strongest files in this chunk are collection errors rather than coverage.
- **Option B gate.** `complete-item-route-adversarial-emulator.test.ts` skips its entire matrix (12 adversarial arms) when the blueprint predates Option B, with a `console.warn` cause and a stated re-enable condition. That satisfies the skip-cause rule but not §14's fail-closed rule: a stale blueprint turns the repo's only adversarial route matrix into a green skip.
- **Evidence lane is unreachable from CI.** `native-script-scan-fault-proof-exunits-emulator.test.ts` is the only file in this chunk gated behind an env var (`MIDGARD_VALIDATION_EVIDENCE`). Per the CI summary only package `test` scripts run, and `test:evidence` is not invoked by any workflow, so its ExUnits ledger — which does carry real acceptance criteria against the §3.3 basis and the L1 cap — never executes in CI.
- **Cross-implementation pins are genuine.** The pinned roots in `script-context-proof.test.ts`, `cek-constant.test.ts` and `cek-data.test.ts` were verified to appear verbatim in `onchain/aiken/lib/midgard/*.test.ak`, computed there by an independent on-chain implementation. These are external-contract vectors, not self-pins, and are the strongest oracles in the chunk. The CI summary confirms `ordered-collection-boundary-aiken` and `cek-core-step-v1` fixture generators run with `--check` in CI, so the vector channel `ordered-collection-boundary.test.ts` writes to is enforced.
- **The dominant defect in this chunk is transcribed measurement tables**, not weak assertions. Eight files (ordered-collection-boundary, cek-observer-boundary, plutus-data-unary-depth-boundary, data-breadth-boundary, field-preimage-carriage-fit, cml-wasm-shadow-stack, native-script-scan bench, and the smaller pins in mpf-proof-fold) carry byte counts, hashes or ExUnits copied out of a previous run. Every one of them sits beside a genuinely self-checking relative assertion (accepted <= limit < adjacent, model reproduces the real signed transaction, plans are interchangeable), which is what makes the transcriptions removable rather than load-bearing.
- **One file is a source-text scanner.** `complete-item-carriage-policy.test.ts` is the only file in the chunk with no runtime execution of the behavior it claims, and the only D. Its blueprint-ABI rows (L223-L249) are legitimate static checks in the wrong place.
- Could not determine: whether the midgard-validation CI job generates `onchain/aiken/plutus.json` before running vitest, and whether the emulator suites' 900-second timeouts are ever actually reached in CI (the package sets no `testTimeout` override, so per-test timeouts are the only bound).
