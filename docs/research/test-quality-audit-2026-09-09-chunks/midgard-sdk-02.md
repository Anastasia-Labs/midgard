## Notes
- Two template families dominate this chunk and separate cleanly on quality. (a) The **Aiken byte-twin** family — fabricated-deposit, fabricated-withdrawal, network-id, transition-trace-l2-transaction, proof-thread-substrate, field-opening, witness-script-decoding, tx-order — carries absolute hex literals stated to be measured from named Aiken modules through `cbor.serialise`, which is exactly the legitimate external-contract pin. (b) The **bare round-trip** family — no-reference-input-carriage.test.ts, native-inclusion-carriage-abi.test.ts, and the wire legs of withdrawn-input.test.ts / withdrawn-reference-input.test.ts — asserts only `Data.from(Data.to(x, S), S) === x`, which cannot fail for any self-consistent schema and establishes no cross-language agreement. Those are the weakest files here and the cheapest to fix (add the Aiken vector; the sibling files show the template).
- The **recording-Lucid fake** is a shared, uncontrolled helper reimplemented three times: `makeRecordingLucid` in scheduler-refresh.test.ts (L114-196), da-attestation.test.ts (L80-146) and da-attestation-rotation.test.ts (L104-140). None has a conformance check against real Lucid, yet scheduler-refresh's expected reference-input *indices* are read straight off its hand-written `makeRedeemerContext`. Only field-preimage-publication-funding.test.ts (62 lines) uses the real Emulator — it is the model the other three should follow.
- **Generic error tags defeat the negative tests** in both DA files: `expectBuildFailure` checks `_tag === "DaAttestationBuildError"` only. Seven refusal cases across the two files are therefore `negative-uncontrolled` in the §5 sense — none establishes that the targeted invalid condition caused the refusal.
- **Golden-channel provenance** is uneven. Three channels have `fixtures:*:sync`/`:check` generator scripts in `demo/midgard-sdk/package.json` and (per ci-summary.txt) their `:check` runs in CI: native-tx-carriage-wire-v1, canonical-decodability-v1, committed-field-shape-v1. `tests/fixtures/cek-context-binding.json` has none of that — no generator, no `:check`, no provenance field, and a repo-wide grep finds cek-context-wire.test.ts as its only reference. That is the one fixture in this chunk whose oracle I could not establish. Note also that the generated fixtures are emitted from this package's own `dist/`, so within a vitest run they are a src-vs-dist comparison; independence rests on the Aiken twin the TS suite cannot execute.
- **Source-text oracles** appear in three files (da-governor-safety L23-38, field-opening L39-107 and L426-439, da-attestation-rotation L53-71). Parsing the Aiken declaration to derive an expected *constructor order* or *constant* is a defensible cross-language static contract and each parser guards against silently returning empty. field-opening L426-439 is the one that oversteps: it greps `native-tx-field-access-v1.ak` for `expect certificate.field_hash == expected_hash` as evidence about the door's runtime behaviour.
- CI: every file here runs under `demo/midgard-sdk`'s `test` script (`vitest run`), which ci-summary.txt confirms is invoked by `.github/workflows/midgard-node-ci.yml`. No file in this chunk is env-gated, skipped, or opt-in; there are no `describe.skip`/`it.skip`/`it.todo` and no early returns. midgard-sdk pins vitest 2.1.8 while every other package uses ^3.0.7 — a divergence worth closing, though nothing in this chunk depends on version-specific behaviour.
- Real production path exercised: pure functions and codecs in all but five files. Real Lucid Emulator (submitted transactions) in field-preimage-publication-funding.test.ts only. Recording fake in scheduler-refresh, da-attestation, da-attestation-rotation. `vi.fn`-mocked Lucid provider in common.test.ts and a two-method literal in user-events-time.test.ts. No Postgres, libp2p or network boundary is touched anywhere in this chunk.
- Review-gate answerability: the Sensitivity question ("what faulty version failed, at which check") cannot be answered from the file for the four bare round-trip files (no-reference-input-carriage, native-inclusion-carriage-abi, and the wire legs of withdrawn-input/withdrawn-reference-input) — no mutation of the schema under test would fail them. It also cannot be answered for the seven generic-tag refusals in the two DA files.
