## Notes

**Production paths exercised.** Three distinct tiers in this chunk:
- Real Lucid `Emulator` + the real compiled Aiken blueprint (`onchain/aiken/plutus.json`, loaded by `tests/support/emulator/blueprints.ts`; overridable via `MIDGARD_REAL_BLUEPRINT_PATH`): the `submit-init-emulator-*`, `cek-core-lifecycle`, `shared-redeemer-item-lifecycle`, `script-integrity-hash-missing-lifecycle` files. The blueprint is gitignored, but `.github/workflows/midgard-node-ci.yml` L189 runs `aiken build --env testnet` with a pinned fork before the package test scripts, so these do run against real validators in CI and fail hard (not skip) if the artifact is absent.
- Real pure production code with no chain: the codec/evidence/replay/machine files (`canonical-decodability`, `missing-signature`, `withdrawn-input`, `prepare-*`, `*-evidence-machine`, `validation-dispute-submit`).
- Mock-only orchestration: the `*-workflow`, `*-central-journal`, `value-conservation-adapter`, `field-preimage-length-mismatch-config` files. Of these only the central-journal files and `value-conservation-adapter` cross a real boundary at all (a real `DirectoryFraudProofWorkflowJournalStore` on a tmp dir).

**Template family 1 -- central journal (8 files repo-wide, 5 in this chunk).** `resolved-output-non-canonical`, `protected-output-signer-missing`, `spend-input-signer-missing`, `output-reference-script-decoding`, `witness-script-decoding` are the same 7 tests with stage names swapped. They mirror 8 copy-pasted `src/<family>/central-journal.ts` modules that differ only by the family string in error messages. Four of the five pass `testOnlyJournalCategoryAlias: "fieldItemWidthIllegal"`, which routes the whole test through a production test-only branch (`process.env.NODE_ENV !== "test"` guard) and derives `workflowId` from a category the production path never uses -- so the identity these suites claim to protect is not the one production computes. `witness-script-decoding` is the only one using the real category.

**Template family 2 -- native-script-invalid evidence machine.** `execution-native-script-invalid-evidence-machine.test.ts` is a verbatim clone of `native-script-invalid-evidence-machine.test.ts`. Both contain a block asserting production batch constants equal transcribed copies of themselves.

**Template family 3 -- van Rossem fit ledgers (3 files here).** `submit-init-emulator-validation-dispute-phase-a-preconditions`, `submit-init-emulator-validation-dispute-script-sources-item-max` and `cek-core-lifecycle` share the same `afterAll` shape. The scenario-count check and the per-transaction memory/CPU ceilings are placed AFTER `if (process.env.MIDGARD_WRITE_FIT_LEDGER !== "1") return;`, so in a normal CI run these suites spend 15-90 minutes of emulator time and then assert only `txHash.toHaveLength(64)` and `transactions.length > 0`. Moving the two ceilings and the count above the early return would cost nothing and convert three long soak suites into real gates. (The ledger-writing side is diagnostic-only and, per the earlier audit ruling, a self-pin; the ceilings are not.)

**Owner-ruling hits.** One clear violation of the hand-maintained-constant rule: `script-integrity-hash-mismatch.test.ts` L263 pins five compiled script sizes. `native-script-invalid` / `execution-native-script-invalid` pin cursor/checkpoint byte widths and batch counts (defensible as a wire contract with the Aiken twin, but transcribed rather than derived). `output-reference-script-decoding-authenticated-workflow`, `field-preimage-length-mismatch-config` and `cursor-family-state` each pin a transcribed copy of a production name list.

**One outright tautology.** `script-integrity-hash-mismatch.test.ts` L207-L216 declares a local `keys` array and asserts it does not contain `"verdict"`/`"evidence"`; the array is test-authored, so the assertion cannot fail regardless of the production actuator.

**Positive templates worth copying.** `submit-init-emulator-value-not-preserved-adversarial.test.ts` is the model for §5 (start from a demonstrated valid scenario; introduce exactly one invalid condition; refuse; then convict honestly on the same thread to prove the refusal was the tamper). `script-integrity-hash-missing-lifecycle.test.ts` closes with `assertCompleteLifecycleCoverage` (src/testing/complete-lifecycle.ts), a genuine fail-closed completeness gate over reason arms, both success directions, base scenarios, authentication seams and cancellable steps -- the only §14-style discovery gate in the chunk.

**Skips / opt-in gating.** No `it.skip`/`describe.skip` and no `test.todo` in this chunk, so no skip-without-cause findings. The only env gating is `MIDGARD_WRITE_FIT_LEDGER` (three files, above) and `MIDGARD_REAL_BLUEPRINT_PATH` (a path override, not a gate). Nothing here is opt-in-only.

**Could not determine.** (1) The provenance of the four "authoritative Cardano language-view vectors" in `script-integrity-hash-mismatch.test.ts` L34-L39 -- the first value also appears in unrelated fixtures across `lucid-midgard`, `midgard-validation` and `midgard-node`, which is consistent with it being a spec-derived constant but is not proof; no citation exists in the repo. (2) Whether `validation-dispute-submit.test.ts`'s canonical-decode redeemer wire pin (L1031-L1042) matches the deployed Aiken decoder -- the file itself states the checked-in blueprint is stale (pre-#620), so that arm is currently unverifiable against the blueprint by construction. (3) I did not read all 2412/2578 lines of the two large files; I read their imports, every `it` boundary, and sampled the decisive blocks (seam refusals, coverage gate, ABI block, validity ranges), so a defect confined to an unsampled interior block could be missed.
