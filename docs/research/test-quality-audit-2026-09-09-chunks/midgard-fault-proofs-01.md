## Notes

- **Production path.** Almost every file in this chunk exercises real production code. The nine large lifecycle files (`field-item-width-illegal`, `receive-purpose-language`, `output-reference-script-decoding`, `missing-redeemer`, `observers-forbidden-...`, `submit-init-emulator-{ledger-rules,max-proof-fit,soundness,cek-value-and-mint,value-and-mint}`, `value-and-mint-asset-yield`, `cek-context-publication`, `state-queue-yield-publication-admission`) run the real Aiken validators on the Lucid emulator with local UPLC evaluation, and their refusals go through `expectOnchainRefusal` (validator refusal, not a builder guard). The workflow files (`min-fee*`, `invalid-signature`, `reference-input-no-idx`, `ledger-absence-artifact`, `canonical-decodability-prepare`, `transition-trace-ledger-replay`, `double-withdraw`) are pure-function/real-MPF tests over the production replay and admission paths. Only `script-integrity-hash-mismatch-proof-carriage.test.ts` is mock-based (transport doubles around a real actuator), and `fabricated-deposit.test.ts` stubs Lucid queries only for the L1 lookup.
- **The fit-ledger family splits in two, and both halves are broken in opposite ways.** The current `onchain/aiken/plutus.json` hashes to `eaf17c21a8fe433f80815a588f73ca39c29f39e40af16649ef897ec0c632b375` (only the transition-trace ledgers carry that digest). (a) The three *transcribed-pin* files (`receive-purpose-language`, `unused-script-witness`, `observers-forbidden-...`) compare a stored JSON field to a copy of the same digest hard-coded in the test - a comparison of two static repo files that can never fail and can never notice the blueprint moved. (b) The four *derived-digest* files (`output-reference-script-decoding`, `execution-source-script-decoding`, `script-integrity-hash-missing`, `spend-input-signer-missing`) do the right thing - and therefore currently FAIL: their stored digests are `3e2e1a78...`, `3e2e1a78...`, `314b1134...`, `3e2e1a78...`, mutually inconsistent and all different from the current build. Since CI runs `aiken build --env testnet` before `pnpm --dir demo/midgard-fault-proofs test`, at most one of these four can be green on any given blueprint. `inspect-contracts.test.ts`'s two hash pins and `state-queue-yield-publication-admission.test.ts`'s `toEqual(pinned)` are in the same boat. This should be checked against the actual CI status: either the fault-proofs job is red, or something (a different `MIDGARD_REAL_BLUEPRINT_PATH`, or a skipped job) is preventing these from running.
- **The correct template already exists in-repo.** `tests/support/measured-fit-ledger.ts` (`createMeasuredFitRecorder` / `verifyMeasuredFitLedger`) derives `blueprintSha256` and `compilerVersion` from the real blueprint, refuses to populate rows from an old ledger, and requires fresh per-source fragments plus a run token to rewrite. `missing-redeemer-lifecycle` and `submit-init-emulator-ledger-rules` use it. The transcribed-pin fit-ledger tests should be rewritten onto it, or replaced by a build-time generator with `--check` in CI (the repo already runs six such fixture `:check` generators for core/sdk/validation).
- **Shared helpers this chunk's verdicts depend on:** `src/proof-fit/van-rossem-fit-ledger.ts` (recomputes margins and refuses non-positive ones at build time - which is why several ledger tests' margin assertions are near-vacuous, the builder would already have thrown), `src/testing/complete-lifecycle.ts` (`assertCompleteLifecycleCoverage`, the lifecycle coverage gate), `tests/support/emulator/expect-onchain-refusal.ts`, `tests/support/emulator/blueprints.ts` (the #610 arity guard that stops an under-applied always-succeeds script from making an emulator journey unfalsifiable), and `tests/helpers/canonical-block-evidence-fixture.ts`.
- **Cross-test state.** Every lifecycle file accumulates measurements and coverage in module-level mutable state and closes with a final "coverage gate / fit ledger" test that depends on all preceding tests in the file having run. Running one test from such a file in isolation (`-t`) makes the gate assert on a partial record; `output-reference-script-decoding-lifecycle` even asserts that the gate THROWS a specific message naming its two declared coverage gaps.
- **Env-gated behaviour:** `MIDGARD_WRITE_FIT_LEDGER=1` switches the lifecycle files from asserting to regenerating the size-plan JSONs, and `MIDGARD_FIT_FRAGMENT_DIR`/`MIDGARD_FIT_MEASUREMENT_RUN` gate the measured-fit fragments. No file in this chunk skips or early-returns when the env is unset, so nothing here impersonates coverage; `MIDGARD_PRINT_FIT`/`MIDGARD_PRINT_PROOF_FIT` only add console output.
- **Could not determine:** whether the fault-proofs vitest job is currently green (audit is read-only, tests were not run), and whether CI's freshly built blueprint reproduces any of the stored digests - the local `plutus.json` is a build artifact dated 2026-09-08 and the digest comparison above is against that file.
