## Notes

- Template families in this chunk, ranked by oracle strength:
  1. **Generated golden channels with a CI `--check` generator and an Aiken twin** - `canonical-decodability.test.ts`, `native-tx-carriage-wire-goldens.test.ts`. Both recompute from `src/` while the generator emits from `dist/` and the Aiken half recomputes under the fork runner, so neither side is authoritative. These are the correct template and should be the target for the weaker files below.
  2. **Hand-written exact CBOR vectors** - `proof-abi`, `scheduler-abi`, `event-abi`, `header`, `double-withdraw`, `field-preimage-length-mismatch`, `native-script-decoding`, `native-tx-field-access`. Legitimate external ABI pins; they hold only because both sides were edited from the same spec, with no mechanical link.
  3. **Round-trip-only** - `native-script-family` (entirely), and large blocks of `min-ada`, `missing-signature`, `missing-native-script-tx`, `da-hash-preimage`, `cross-block-duplicate-event`, `fault-proof` L177-1236. `Data.from(Data.to(x,S),S) === x` cannot detect a symmetric tag/field-order error and is the dominant weakness in the chunk.
- **Shared helper the chunk depends on**: the fixture `demo/midgard-validation/tests/fixtures/validation-auxiliary-witness-v1.generated.json` is produced by `demo/midgard-validation/scripts/generate-validation-auxiliary-witness-v1-fixture.mjs` from that package's `dist/` encoder. Unlike the other two golden channels, `ci-summary.txt` does not list it among the fixture `:check` generators run in CI, so the SDK test can pass against a stale fixture. Worth confirming separately.
- **Biggest single CI gap**: `fault-proof.test.ts` L1856-1858 early-returns the whole validation-trace-dispute builder test (~485 lines, including the only 14KB reference-script size gate in the chunk) unless `MIDGARD_REAL_BLUEPRINT_PATH` is set. No workflow sets it. The file already resolves the in-tree blueprint by default at L82-83, so the gate is vestigial. `validation-resolver-applied-hashes.test.ts` L21-27 documents fixing exactly this pattern under #609; `fault-proof.test.ts` and `user-event-contracts.test.ts` L28 still read the env var (the latter harmlessly, as a redirect only).
- **Duplicated coverage**: the frozen `FieldCarriageV1`/`FieldViewV1`/`FieldPreimageCertificateMintRedeemerV1` constructor indexes are pinned in both `native-tx-carriage-wire-goldens.test.ts` (L136-170) and `native-tx-field-access.test.ts` (L84-95, L141-152, L222-232). The duplication is deliberate in the goldens file (fixture and constants pinned separately) but `native-tx-field-access`'s unique contribution is the Aiken-source declaration-order parse, not the index literals.
- **Production paths actually exercised**: real Emulator with `localUPLCEval` (real Plutus execution of the state-queue validator) in `state-queue.test.ts`; real Emulator in `phas-membership.test.ts`; real CML for min-Ada and transaction sizing in `validation-proof-item.test.ts` and `availability-challenge.test.ts`; real blueprint (`onchain/aiken/plutus.json`) parsing in `fault-proof`, `user-event-contracts`, `phas-membership`, `state-queue`, `validation-resolver-applied-hashes`; everything else is pure functions over the SDK's own codecs. Only `hub-oracle-nonce`, `state-queue-validity` and the fetch legs of `event-abi` use mocked Lucid, and each scopes its claim to builder/filter behaviour rather than submission.
- **CI**: `ci-summary.txt` says the `midgard-sdk` package `test` script runs in `.github/workflows/midgard-node-ci.yml`, so every file here executes except the env-gated leg above. `midgard-sdk` pins vitest 2.1.8 while every other package uses ^3.0.7 - not a test-quality defect, but it means these suites run under a different runner than the rest of the repo.
- **Could not determine**: whether `validation-auxiliary-witness-v1.generated.json` has a `--check` invocation anywhere in CI (the package.json grep for a `:check` script returned nothing and I did not read the workflow files directly, per the read-only/no-Bash constraint); and whether the Aiken-side pins in `native-script-decoding.test.ts` are asserted by a matching Aiken test (the header claims they were measured from `thread_fixture_v1.ak`, which I did not open).
