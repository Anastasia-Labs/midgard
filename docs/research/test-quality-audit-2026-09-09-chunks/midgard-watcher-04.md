## Notes
- Template family: `indexers/proof-thread-indexer.test.ts` and `indexers/user-event-indexer.test.ts` are the same architecture at ~4.3k lines each. Both build genuine Cardano transactions with CML (bodies, mints, redeemer lists, canonical CBOR, real body-hash derivation via `computeHash32`), encode datums/redeemers against the real `@al-ft/midgard-sdk` Plutus schemas, stand up real listening TLS servers and attest real external-provider transports, then drive the real indexer, finality, multi-provider-consistency and rollback engines. Negatives are built by mutating one field of a demonstrated-valid scenario and re-deriving all dependent digests, so the refusal is caused by the targeted condition rather than by a digest mismatch. There is essentially no duplicated coverage between them (different protocol surfaces).
- Shared helper `tests/support/canonical-json.ts` deliberately re-exports the production canonicalizer (`watcherCanonicalJson` / `watcherSha256CanonicalJson`) and documents why. In these files it is used to forge internally-consistent hostile inputs (so the attack survives the digest gate and reaches the semantic check), not as an independent oracle for the digest algorithm itself. Consequence: nothing in this chunk independently pins the watcher canonical-JSON encoding; if that walk changed, these suites would follow it silently. That is a real gap, but it belongs to whichever file pins the canonical form, not to these.
- Shared helper `tests/support/tls-transport-fixture.ts` shells out to the `openssl` binary and the proof-thread suite creates its fixture directory under `/dev/shm`; several files here `mkdtemp` under `/var/tmp`. These are Linux/host assumptions, but they fail closed (a missing `openssl` or `/dev/shm` aborts `beforeAll`), so they do not impersonate coverage.
- `tests/support/deployment-authority-fixture.ts` is the chunk's central fixture: it builds the signed deployment identity, applied script hashes and fraud-proof catalogue that five of these seven files bind against. Its own correctness is load-bearing for most verdicts in this chunk; it is not audited here.
- Mocking is confined and declared. `watcher-runtime.test.ts` mocks the trusted-head sidecar, funding overlay, fault-proof application and L1 acquisition, with a comment stating they establish no release readiness — the storage path it claims (SQLite, archive hashing, protected checkpoint admission) runs for real. `resolved-block-observation.test.ts` mocks only the upstream Kupmios raw readers and the transport-attestation lookup, with the same disclaimer, while the block bytes come from a real Conway block fixture decoded through CML. `retained-da-runtime.test.ts` doubles only the libp2p transport factory. None of these replaces the decision the test claims.
- Cost: `proof-thread-indexer.test.ts` L2597 builds a ~17 MB hex payload (`"ab".repeat(8_500_000)`) and carries a 60s timeout, and two further cases carry 30s timeouts, against a watcher vitest config of `maxForks 2` / `testTimeout 60s`. The claim (aggregate restart evidence spread across retained transitions must be refused) is legitimate, but it is the most expensive single case in the chunk and sits close to the configured timeout.
- Refusal granularity: the user-event suite asserts most refusals as `deriveWatcherUserEventObservation(...) === null`, a single undifferentiated rejection shared by dozens of distinct causes. Causality is established by construction (one-field mutation from a demonstrated-valid base), which satisfies §5, but a reason-code surface on the derive path would make these far more discriminating. The proof-thread suite does better, asserting specific `reasonCodes` (`malformed_public_context`, `stale_state`, `rollback_authority_mismatch`, `rollback_mismatch`).
- CI: the `midgard-watcher` package `test` script runs in `midgard-node-ci.yml` and `midgard-watcher-ci.yml`, so all seven files execute. No file in this chunk is env-gated, skipped, or opt-in; no `it.skip`/`it.todo` anywhere.
- Not determined: I did not read the ~2,200 lines of fixture builders in each indexer file end to end (I read the full fixture prologue of the proof-thread file, its complete test bodies, and sampled the user-event fixture layer). A defect hidden in an unread builder — e.g. a scenario helper that silently degrades a hostile input — would not have been caught. Both files' assertions are consistent with the builders I did read.
