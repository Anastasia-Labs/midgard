## Notes

- **CI:** every file in this chunk runs under the `midgard-core` package `test` script, which `.github/workflows/midgard-node-ci.yml` invokes. Nothing here is env-gated, `describe.skip`ped, or opt-in; there are no `it.skip`/`it.todo` in the chunk. Three fixture `:check` generators for this package (`native-tx-field-access-v1`, `native-tx-field-items-v1`, `native-tx-vector-v1`) also run in CI, which is what makes the golden suites below more than self-comparison.
- **Production path:** the chunk is overwhelmingly pure in-process code with no mocks. Only two files cross a real external boundary — `availability-operation-journal.test.ts` (a real on-disk SQLite file plus a spawned child process killed with SIGKILL) and `da-libp2p-identity.test.ts` (real `@libp2p/peer-id`, real temp files). `deployment-manifest-identity.test.ts` builds a real MPF trie with `@aiken-lang/merkle-patricia-forestry`. Several suites use CML/lucid as an *independent* oracle rather than as a dependency under test (`blake2b-*-trace` via `@noble/hashes`, `ledger-output-scan` via CML `Value`, `plutus-data-wellformed` differentially against CML `Data.from`, `native-cardano-redeemer-bridge` and `native-redeemer-deep-data` through real CML redeemers). `vi.fn` appears only as a *negative* probe (asserting a decompressor or `run` callback was NOT called), never to stub a decision. There is no `stubbed-decision` or `mock-only-boundary` anywhere in this chunk.
- **Three tiers of oracle quality.** (1) *Genuinely independent*: `blake2b-224-trace`, `blake2b-256-trace` (noble), `plutus-data-wellformed` (differential CML corpus of 6,000+ cases), `da-payload-sizing` (model vs real encoders), `consensus-validation` (binary-searched boundary), `native-tx-carriage` (paired neighbour values). (2) *Cross-language golden channel with a CI `--check` generator*: `native-tx-field-access-goldens`, `native-tx-field-items-goldens`, `native-tx-field-item-decoders`, `native-codec`. These are the correct template. (3) *Hex constants annotated "the Aiken vector" with no generator, fixture, or `--check`* — `cek-source-blob`, `cek-data-bytes`, `cek-data-integer`, `cek-data-frame`, `cek-data-traverse`, `cek-blob-frontier`, `cek-proof`, `blake2b-*-trace`, `ledger-output-scan`, `ledger-output-proof`, `ledger-output-commitment`, `ledger-output-value`, `validation-trace`, `script-proof`, `bounded-blob`, `native-script-decoding-engine`, `script-language-views`. Roughly 60 pinned control encodings and leaf hashes sit in this tier. Individually each is defensible (the control layout *is* an on-chain contract); collectively they are the chunk's largest by-construction gap, and moving them into tier 2 is one mechanical change per family.
- **The three weakest files, all for the same reason** — hand-maintained constants the owner ruled out: `consensus-profile.test.ts` (C, ~40 transcribed measurement constants, comments recording repeated re-pins), `deployment-manifest-identity.test.ts` (C, a 43-name ordered roster plus 524/517/518 counts plus a manifest-id pin re-pinned five times), `plutus-data-deep-datum-retained.test.ts` (C, four sha256/length pins whose comment documents a hand re-pin). `cek-data-ledger-blob.test.ts` (C) is the same pattern at smaller scale and also duplicates coverage. In every one of these the *valuable* half is a derivation or a real round trip that is already self-checking; the pins can be deleted without losing detection capability.
- **Wall-clock assertions used as gates** appear three times: `plutus-data-wellformed.test.ts` L381-L391 (`Date.now()` under 5 s), `cek-proof.test.ts` L2306 (`performance.now()` under 2 s), `da-request-deadline.test.ts` L21-L24 (250 ms envelope on a 25 ms timeout). None is a defined performance workload with an environment; each is a rough non-regression tripwire that a loaded CI runner can flake. The first two are redundant beside structural assertions in the same test.
- **Duplicated coverage:** `da-transport.test.ts` and `da-transport-vectors.test.ts` both freeze the limits table, gossip topics, protocol ids and enum code maps; the second is a strict superset on that block. `cek-data-ledger-blob.test.ts` re-covers bytes-node hashing already proven with real Cardano framing in `cek-data-bytes.test.ts`.
