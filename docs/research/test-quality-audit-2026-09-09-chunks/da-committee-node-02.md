## Notes
- CI: the da-committee-node package `test` script runs in .github/workflows/midgard-node-ci.yml, so every file here executes except postgres-store.test.ts, whose gating variable WATCHER_TEST_DATABASE_URL is set nowhere in the repo. That file is the chunk's only CI gap and the only real-Postgres coverage of the watcher store; PostgresWatcherStore's quarantine/outbox/row-identity semantics are therefore unprotected in CI even though JsonFileWatcherStore's equivalents are covered by store-factory.test.ts.
- Shared helper `tests/helpers.ts` is load-bearing for four files. `makePayloadFixture` (L205-215) derives the fixture header's eight roots by calling the production `computeDaPayloadRoots`, so any test that compares derived roots to `fixture.header` is self-comparing; tests that instead perturb a payload member and require a specific refusal code (payload.test.ts, libp2p-payload-protocols.test.ts) are unaffected because the mismatch is introduced after the header is fixed.
- Production paths exercised: real fs-backed JsonFileWatcherStore (store-factory, peer-coordinator, libp2p-payload-protocols), real Ed25519 signing and committee validation (peer-coordinator, startup-da-params), real midgard-core CBOR wire codecs (libp2p-payload-protocols, peer-coordinator gossip), real TCP+Noise libp2p between the public listener and the midgard-watcher transport (libp2p-runtime L321-394 only). L1 submission is stubbed everywhere in this chunk (coordinator.test.ts submitter, peer-coordinator onChainCoordinator) — no file here claims otherwise.
- Duplicated coverage: the availability-commitment/signature-record fixture builders and the quarantine-terminality assertions are repeated near-verbatim across store-factory.test.ts, postgres-store.test.ts and peer-coordinator.test.ts. That duplication is justified while it covers two distinct store implementations, but the fixture builders themselves are three copies of one thing and could be shared through helpers.ts.
- Concurrency in this chunk is generally handled with promise gates and bounded waitFor loops rather than sleeps; the two exceptions are noted per file (peer-coordinator L394, libp2p-runtime L561).
- Not determinable: whether the libp2p-runtime real-TCP case (L321-394) is reliable in the CI sandbox — it binds 127.0.0.1:0 and looks self-contained, but I did not run it (read-only audit).
