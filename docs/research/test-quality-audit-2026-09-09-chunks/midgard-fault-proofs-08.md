## Notes

- Template families in this chunk:
  - **Van Rossem fit ledgers** (`missing-script-source-fit-ledger`, `missing-redeemer-fit-ledger`, `invalid-range-wrongful-rejection-fit-ledger`) are the chunk's only failing grades. All three transcribe measurements a *different* suite produced, hold a blueprint digest/compiler version they never verify against the real blueprint, and close with a self-comparison (the JSON file against the same in-test table, or the file's own digest against its own body). In the first two, the headline margin assertion also restates an invariant `buildVanRossemFitLedger` already enforces by throwing (`src/proof-fit/van-rossem-fit-ledger.ts` L80-88), so it cannot fail. Fix once, for the family: have the measuring lifecycle suite emit the ledger with the digest derived from `realBlueprintPath` at test time, and add a `--check` step in CI. `cek-material-traversal-maximum` and `native-script-decoding-installed-lifecycle` already do the derivation correctly, but only write under `MIDGARD_WRITE_FIT_LEDGER=1`.
  - **Registered-chain parity** (`field-item-width-illegal`, `protected-output-signer-missing`, `spend-input-signer-missing`, `mint-declared-asset-limit`) all end with the same `buildRegisteredChainFixture` block comparing applied script hashes to the SDK-registered chain. Both sides are derived at test time from the same blueprint, so these are genuine cross-path checks, not hand-updated pins - a good template.
  - **Adversarial emulator polarity** (`mint-authorization`, `missing-native-script-tx`, `input-set-uniqueness`, `withdrawn-reference-input`, `da-hash-preimage`) is the strongest family here: each drives the real Aiken validators under `localUPLCEval`, refuses at the honest submitter's local guard AND again through a raw builder that skips that guard, and asserts the thread was left where it was. The pattern earns its cost.
  - **Fully mocked orchestration tests** appear inside otherwise-real files (`receive-purpose-language` L332-387, `field-item-width-illegal-workflow` L239-269/L385-410, `field-item-width-illegal` L266-284). Only the last is worthless (it asserts a locally-defined fake against itself); the others verify journal/resume orchestration and do not oversell it.
- **Constant-list pinning** recurs across the chunk: `*_CONFIG_KEYS`, `*_MANIFEST_CONTRACTS`, `Object.keys(workflow)`, `LINEAR_FAMILY_SPECS`. `missing-redeemer-registration.test.ts` consists of nothing else, which is why it is the one D outside the ledger family. The property they are reaching for ("runtime config carries no callback authority") is type-enforceable.
- **Execution paths.** Real Lucid emulator + real Aiken validators under local UPLC evaluation: files 1, 3, 4, 5, 6, 8, 18, 19, 21, 22, 26, 27, 33, 35, 36, 40. Real canonical replay over built DA payloads (no chain): 7, 12, 29, 30, 38. Pure functions with real crypto (node `crypto` Ed25519 / CML): 10, 14, 15. Pure functions only: 2, 13, 16, 23, 24, 25, 28, 31, 34. Fake HTTP `fetchImpl` for the node adapter (a deliberate transport double): 11, 32, 37.
- **Opt-in / env gating.** No file in this chunk is skipped or early-returns without an env var. Two env vars only *widen* behavior: `MIDGARD_WRITE_FIT_LEDGER=1` (cek-material-traversal-maximum, native-script-decoding-installed-lifecycle) and `MIDGARD_UPDATE_*_LEDGER=1` / `MIDGARD_PRINT_PROOF_FIT=1`. Nothing impersonates coverage.
- **CI.** The whole chunk runs under the `midgard-fault-proofs` package `test` script in `.github/workflows/midgard-node-ci.yml` (isolated forks, maxForks 8), so all 40 files execute; none are orphaned. The fit ledgers therefore run in CI but, as noted, cannot fail for a production reason.
