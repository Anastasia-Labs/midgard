## Notes

- **Whole-chunk shape.** Eight of nine files exercise real production paths: real MPF stores on disk (transition-trace), real Lucid emulator + real compiled validators + `localUPLCEval` (cek-material, operator-lifecycle, tx-order-carriage), real Harmonic UPLC evaluation of real Aiken-compiled guards (midgard-local-script-eval), real Postgres with migrations (retention-enforcement, tx-order-carriage DB leg), and real WebSocket/HTTP servers (tx-order-carriage, da-libp2p port-conflict test). Only `da-payload-libp2p-producer.test.ts` is predominantly mock-driven, and only for the peer transport.
- **No tautologies or self-pins found in this chunk.** No file compares a digest to a copy of itself, and no file pins a compiled-script hash or byte size. The only transcribed constants are: `retention-enforcement.test.ts` L82-L84 (907_200_000 / 1_296_000_000 / 388_800_000 ms), which encode the protocol retention window and deployed window - legitimate spec constants under the owner ruling, though they could be derived from the imported `MIDGARD_RETENTION_WINDOW` rather than typed out; and `operator-lifecycle-emulator.test.ts` L45 (`900_000_000n` required bond), which carries an in-file comment deriving it from `env/testnet.ak` (slashing_penalty + fraud_prover_reward) - correct provenance, but still a hand-maintained mirror of an Aiken env constant that `SDK.getProtocolParameters` already exposes; reading it from the SDK would make it self-checking.
- **Partially circular oracle in transition-trace-builder.** `snapshotTraceOracle` (L143-L203) is an independent full-recompute model for `finalUtxosRoot`, the per-step pre/post roots and `transitionTraceRoot`, but at L180 it calls the production `buildEventToStepMembersFromTrace` to produce its *expected* `eventToStepMembers`/`eventToStepRoot`. Those two assertions (L233, L237) therefore only check that the incremental path feeds that function the same inputs, not that the function is right. The dedicated duplicate-key and index-ordering tests (L886, L769) partly compensate.
- **Error-category weakness is the chunk's recurring gap.** `transition-trace-builder.test.ts` has nine negative cases that assert only `result._tag === "Left"` (L529, L557, L598, L735, L808, L824/L845, L864, L882, L933); a fixture/typing failure inside `buildTransitionTraceResult` would satisfy every one. The inputs are tightly controlled and several pair the refusal with an unchanged-root check, which is why this stays a B rather than a C, but none names the refusal. Same defect at `operator-lifecycle-emulator.test.ts` L623 and `phase2-benchmark-report.test.ts` L750-L769 (a twelve-case loop with bare `.toThrow()`).
- **Stale test title.** `retention-enforcement.test.ts` L750 is named "retains a block_end_time exactly at the cutoff and **prunes 1ms past it**" but its second half (L767-L783) asserts `{ deleted: 0, remaining: 1 }` - it does not prune. The assertion appears correct (a merge-only terminal outcome without availability-release evidence is retained regardless of the horizon; contrast L718 where `seedPublished` supplies that evidence and 1 ms past the cutoff does delete). The title is what is wrong, and it would mislead any reviewer answering the Contract gate question for that case.
- **Opt-out env gating.** `retention-enforcement.test.ts` L189 and `tx-order-carriage-l1-observation.test.ts` L792 share `const dbEnabled = process.env.MIDGARD_SKIP_DB_TESTS !== "1"` + `describe.skipIf`. This is opt-out (default on), so CI runs it, and neither impersonates coverage under normal invocation - but setting that one variable silently drops the entire DB-backed retention suite and the only end-to-end forced-order ingestion assertion with no skip cause recorded in the run. Worth a fail-closed guard in CI (assert the variable is unset) rather than a code change.
- **Producer-schema gap in the Phase 2 gate test.** `phase2-benchmark-report.test.ts` verifies the *verifier* against hand-authored report objects only. Nothing in this file (or, per ci-summary, in CI) checks that the real benchmark producer emits reports carrying these field names, so a producer-side rename would leave the gate green against fixtures while the real gate stopped seeing the fields. A shared schema module or one recorded producer sample fed through `verifyStageBReport` would close it.
- **Fixture fakes whose own correctness the chunk depends on.** `tests/helpers/local-l1-observation.ts` (24 kB) reimplements Ogmios chain-sync over a real WebSocket and Kupo over real HTTP; every claim in `tx-order-carriage-l1-observation.test.ts` rests on its fidelity. The file is unusually honest about this (its header comment scopes the claim to "a source exists", and it pins the `?resolve_hashes` asymmetry and the v2.10.0 floor on the wire precisely so a harness simplification cannot green a broken reader), but per §8 a semantic fake still wants a conformance check against real Kupo/Ogmios. `tests/helpers/real-midgard-contracts.ts` loads the *real* state-queue and operator validators with always-succeeds placeholders elsewhere, so `operator-lifecycle-emulator.test.ts` does exercise the validators it claims.
- **Blueprint dependencies resolve.** `demo/midgard-node/blueprints/always-succeeds/plutus.json` is present and committed (only `build/` is gitignored there), so `midgard-local-script-eval.test.ts` is not silently dependent on a locally-built artifact. `cek-material-publication-emulator.test.ts` reads the real `onchain/aiken/plutus.json` (or `MIDGARD_REAL_BLUEPRINT_PATH`) and throws if the validator is absent - fail-closed.
- **Duplicated coverage worth consolidating.** `operator-lifecycle-emulator.test.ts` L639, L692, L739, L821, L880, L925 are the same register-then-activate assertion under six coin-selection stress profiles, at 240-420 s timeouts each. Their shared snapshot-clone keeps the deployment cost single, but the marginal protection after the first fragmented and first churned case is small; folding them into one `it.each` over profiles would keep the risk model and cut both runtime and diagnosis cost.
- **Could not determine:** whether `scripts/verify-phase2-benchmark-report.mjs` is ever invoked against real produced reports anywhere (ci-summary lists other midgard-node scripts in CI but not this one); and whether the Phase 2 report producer and this verifier share a field-name definition. Both would require reading the benchmark producer scripts, which are outside this chunk.
