## Notes
- **Chunk shape.** 38 files, overwhelmingly real-emulator fault-proof lifecycles plus pure-function evidence/detector suites. Almost all exercise real production paths: the real applied Aiken validators on a lucid `Emulator`, real `@aiken-lang/merkle-patricia-forestry` tries, the real canonical CBOR codecs and the real proving cores. Only two files (`missing-signature-adapter`, the lease-coordinator half of `remove-fraudulent-block`) are mock-boundary tests, and one (`transition-trace-challenger`) fakes only the libp2p hop.
- **The one clear defect family is transcribed measurements.** Three files carry hand-maintained numbers that a behavior-preserving rebuild invalidates: `field-preimage-length-mismatch-fit-ledger.test.ts` (worst -- 34 transcribed rows plus a literal blueprintSha256 compared to a JSON copy of themselves; zero production measurement executed), and the two `option-b-direct-frontier-*` files (stage byte sizes and execution units). The repo already contains the correct template in `tests/support/measured-fit-ledger.ts`: `verifyMeasuredFitLedger` hashes `realBlueprintPath` at test time, reads `preamble.compiler.version` from the blueprint, regenerates rows from freshly captured submissions under `MIDGARD_WRITE_FIT_LEDGER=1`, and cross-checks the row-name set. `cek-context-lifecycle.test.ts` and `invalid-range-wrongful-rejection-lifecycle.test.ts` already use that derivation style.
- **Shared helpers the chunk's verdicts depend on.** `tests/support/emulator/measurement.ts` derives `l1ByteMargin` from `PROTOCOL_PARAMETERS_DEFAULT.maxTxSize`, and `tests/support/emulator/proof-fit.ts` (`expectProofFit`) derives the execution ceilings as 80% of the emulator's own protocol parameters -- so every `expectProofFit`/`l1ByteMargin > 0` assertion in this chunk is derived, not pinned. The literals `15_872` and `16_384` appearing in the four `*-publication-fit` files bypass those helpers and restate the same budget by hand.
- **Silent skip gate.** Both `submit-init-emulator-option-b-direct-frontier-*.test.ts` files sit under `describe.skipIf(!realBlueprintSpeaksOptionBV1())`. The skip reason and re-enable condition are printed (`OPTION_B_SKIP_REASON`), satisfying the skip-cause rule, but a stale `onchain/aiken/plutus.json` makes both files pass green in CI with zero journeys run. `cek-context-lifecycle.test.ts` has a weaker version of the same problem: its `expect(completed).toBe(24)` discovery check only runs under `MIDGARD_WRITE_FIT_LEDGER=1`, so a dropped or renamed case is invisible in a normal CI run.
- **CI.** `demo/midgard-fault-proofs/vitest.config.ts` includes `./tests/**/*.test.{ts,tsx}` and the package `test` script runs in `.github/workflows/midgard-node-ci.yml`, so every file in this chunk does run in CI (isolated forks, maxForks 8). `tests/support/vitest.supplemental.config.ts` additionally re-runs `submit-init-emulator-transition-trace.test.ts` single-forked as a release measurement; that is a second execution of an already-required test, not extra coverage.
- **Test-only production hooks.** `submitInputSetUniquenessStep02` accepts `unsafeSpendFieldRawUtxoForTest` and `submitRaw*` builders exist for several families. These inject faults rather than bypass the decision under test (the on-chain validator still runs), so they do not violate the "no test-only branch through the behavior under test" rule, but they are production-surface affordances that only tests use.
- **Duplicated fixture builders.** `no-reference-input-forced-replay.test.ts` and `non-existent-input-forced-replay.test.ts` each contain a ~210-line canonical-block fixture builder that differs only in `source_kind` and the family module; the same `buildCanonicalBlockFixture` + counted-root scaffolding is re-derived rather than shared, so a bug in one copy silently weakens one family.
- **Not determined.** I did not execute any suite, so I could not confirm which cases actually run (notably whether `realBlueprintSpeaksOptionBV1()` is currently true against the checked-in blueprint, or whether the 24 `cek-context-lifecycle` cases all pass); and I did not verify that the Aiken constructor order transcribed in `structural-na-event-window-variants.test.ts` still matches `onchain/aiken/lib/midgard/fraud-proofs/transition-trace/proof.ak`.
