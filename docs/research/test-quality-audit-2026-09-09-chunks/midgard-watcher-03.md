## Notes

- **CI**: every file here runs under the `midgard-watcher` package `test` script, which is wired in both `midgard-node-ci.yml` and `midgard-watcher-ci.yml`. No file in this chunk is env-gated, skipped, or quarantined; there is no `it.skip`/`describe.skip`, no `process.env` gate, no `Date.now()`/arbitrary-sleep oracle, and no snapshot files. The only `process.env` reference is `user-event-history.test.ts` L3201, a *fallback override* for the blueprint path, not a gate — with the default `onchain/aiken/plutus.json` being a build artifact, that test fails closed (readFile throws) if the Aiken blueprint was not built before the watcher suite, which is the correct direction but makes that one case dependent on build ordering in CI.
- **Real production paths exercised**: real `node:sqlite` (replay-transcript-store), real filesystem journal + injected FS port (fault-decision-journal), real Conway block CBOR decode via `admitWatcherNativeRollForwardBlock` (local-kupmios, user-event-reference-authority), real Lucid/`Emulator` transaction building and a real spawned native-chain-sync binary reading `blocks.json` (emulator-chain-transport, user-event-history), real `node:tls` server with embedded test certificates for external-provider transport attestation (rollback-engine), real MPF root construction and the canonical `midgard-validation` Phase-A/Phase-B machine (block-replay). Purely fake-backed: `state-queue-runtime` (store+source), `user-event-history` (durable backend/trusted-head/archive), `user-event-reference-authority` (three `vi.mock`ed upstream modules).
- **Shared helpers this chunk depends on** (their own correctness is load-bearing and not audited here beyond spot checks): `tests/support/replay-transcript-archive-fixture.ts`, `tests/support/deployment-authority-fixture.ts`, `tests/support/user-event-origin-fixture.ts`, `tests/support/state-queue-observation-fixture.ts`, `tests/support/settlement-authority-scenarios.ts`, `tests/support/user-event-authority-scenarios.ts`, `tests/support/watcher-opaque-authority-harness.ts`, `tests/support/emulator-chain-transport.ts`, plus `@al-ft/midgard-validation/tests/validation-fixtures`. `emulator-chain-transport.test.ts` is the conformance check for one of these fakes (legitimate per §8), but the other support fixtures have no equivalent conformance file in this chunk.
- **Fixture-testing bundled into production tests**: `block-replay.test.ts` L1356-1381 asserts a 23-boolean `repeatIsolationEvidence` object about W15/W16 *fixture-factory* lease/dispose/isolation behaviour, all computed in `beforeAll` (L334-508), inside a test titled "replays a Deposit before an L2 spend". It should be split into its own fixture-conformance file.
- **Weak positives worth noting**: `local-kupmios-native-observation.test.ts` L271-276 builds the "accepted" raw block *from* the natively decoded block, so the positive case cannot fail by construction; only the five hostile-substitution cases carry information.
