# A1 — bounded foreign payload retrieval

Implemented option (a): the node now retrieves missing foreign payloads through the actual watcher V1 client and its existing TCP, Noise and Yamux transport. It uses a narrow `midgard-watcher/public-da-client` package export, rather than maintaining another DA engine. The node has a production dependency on that package; the reverse watcher-to-node dependency remains development-only. The running node calls the new reconciliation fiber, so this is an operational consumption path, not an unused helper. Sources: [public export](../../../demo/midgard-watcher/package.json#L18), [node wiring](../../../demo/midgard-node/src/commands/listen.node-fibers.ts#L89), [fiber](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.ts#L102).

Option (b) is kept alongside the fetch, as pushed, until the owner rules on it. The commit gate's window rule lets a commit proceed past an unverified foreign window once every event table is ingested past that window's end and no event the build would carry lies inside it. An event indexed into the window later makes it block again. The rule never lifts the two unconditional verdicts: a stored `invalid` (a malformed header, or a held payload that failed verification) and a verified present event awaiting finalization. A retrieved payload resolves a row outright; option (b) only stops a missing one from holding unrelated commits. A timeout, failed episode or expired cooldown changes only network retry scheduling. It never marks evidence resolved or deletes it. Sources: [window rule](../../../demo/midgard-node/src/workers/t2-foreign-event-reconciliation.foreign-window-gate.ts#L146), [historical alternatives](source-context.md#L30), [present-event hold](../../../demo/midgard-node/src/workers/t2-foreign-event-reconciliation.resolve-t2-foreign-event-evidence.ts#L267), [execution limitation](E1.md).

Each fetch has a 60-second deadline, one concurrent request, and a per-request timeout capped at ten seconds. The watcher already bounds negotiation, frames, envelopes, chunks and decompression. The node records up to 64 retry states in memory. It makes at most four failed fetches in one active episode, with 30-, 60- and 120-second backoffs, then gives that header a five-minute cooldown. Expiry clears the retry budget automatically. Unused states also expire, so orphaned headers cannot permanently occupy the cache. These budgets persist across fiber ticks but reset on a process restart; durable foreign evidence does not reset. Both the client deadline and retry intervals use monotonic clocks. Sources: [runtime bounds](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.ts#L154), [retry policy](../../../demo/midgard-node/src/da/foreign-da-retry-policy.ts#L5), [expiry](../../../demo/midgard-node/src/da/foreign-payload-retriever.ts#L47).

The database scan pages by header hash, remembers its cursor, and wraps only at the end. Each page contains at most 16 header keys. A tick ends after its first successful download or stored-payload consumption; a failed row passes to the next, so one tick can make up to 16 failed fetches in sequence, each within its 60-second deadline. A fixed first page cannot monopolize retrieval. Stored payloads remain eligible for consumption after the history owner becomes available again, with two exceptions. A row holding a stored `invalid` verdict already failed against the payload this node holds. Consuming that payload again would replay the same verdict, and a download cannot replace it, because the payload store refuses to overwrite different bytes; so the fiber leaves such a row alone. It fetches only for a row with no stored payload. A header whose event roots and counts disagree is malformed on its face, so no payload can repair it and the fiber never fetches for it. One residual gap remains: an `invalid` row whose stored bytes are wrong stays held, because no automatic path replaces those bytes. Each row is isolated: a failure on one row, a refused overwrite among them, is logged and the pass moves to the next row. The retention sweeper's single pruner owns the retention horizon (see A3); this fiber does not prune safety evidence. Sources: [row action](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.ts#L57), [per-row isolation](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.ts#L75), [paged scan](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.ts#L207).

Transport success is only the first check. The finalized deployment manifest is verified, its ID must equal both runtime-manifest deployment IDs, and the transport authenticates the configured peer ID. Custom-network private addresses require the exact verified manifest and peer configuration. The retained header must match its immutable hash and evidence columns. Before the node stores fetched bytes, it checks the envelope SHA-256, V1 schema, deployment marker, consensus profile and header binding, decodes the canonical envelope, reconstructs all eight committed roots, and checks the declared counts against the arrays and header. Retrieval also checks the count relationships enforced by the DA table: total events equal the category sum, transition steps equal total events, and validation traces equal forced plus L2 transactions. A peer whose content fails those checks is rejected before selecting it over another peer. Sources: [manifest authority](../../../demo/midgard-watcher/src/storage/public-da-client.manifest-config.ts#L37), [transport address authority](../../../demo/midgard-watcher/src/storage/public-da-libp2p-transport.ts#L313), [retained header](../../../demo/midgard-node/src/workers/t2-foreign-event-reconciliation.decode-retained-header.ts#L11), [root reconstruction](../../../demo/midgard-node/src/workers/t2-foreign-event-reconciliation.resolve-t2-foreign-event-evidence.ts#L66), [additional count relationships](../../../demo/midgard-node/src/da/foreign-payload-retriever.ts#L11), [storage authentication](../../../demo/midgard-node/src/da/foreign-payload-store.ts#L19).

The consumer stores authenticated bytes first, then invokes ordinary T2 reconciliation through `runHistoryProducer`. That existing owner API admits the work and supplies its current generation guard; the reconciliation's SQL writes still require the history authority. An unavailable or superseded owner leaves the row held. Only the existing reconciliation can mark it resolved, and foreign event inclusion still requires the separate finalization capability. Review caught a missing owner admission in the first integration; the production consumer and its regression now exercise this gate. Sources: [actual consumer](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.consume-payload.ts#L10), [owner admission](../../../demo/midgard-node/src/services/event-history-producer.ts#L234), [reconciliation](../../../demo/midgard-node/src/workers/t2-foreign-event-reconciliation.reconcile-retained-foreign-tip-entry.ts#L29).

Client shutdown aborts active I/O and content validation, rejects queued permits, and prevents later peer dialing. Content validation shares the fetch deadline, so a hung asynchronous validator cannot retain a permit forever. The node registers scoped finalizers before transport startup, bounds startup to ten seconds and cleanup to five seconds, and closes the client before stopping its transport. A start that fails (the DA runtime manifest cannot be loaded or does not match, or the transport does not start in time) never ends the node. The fiber retries it with a backoff that doubles from 30 seconds to a five-minute cap. Until a start succeeds it raises `foreign_da_retrieval_unavailable` as a readiness reason, which escalates after 15 minutes and holds no fiber. Source: [client shutdown](../../../demo/midgard-watcher/src/storage/public-da-client.watcher-public-da-client.ts#L815), [bounded validation and permit revocation](../../../demo/midgard-watcher/src/storage/public-da-client.validate-inner-payload.ts#L10), [transport startup cancellation](../../../demo/midgard-watcher/src/storage/public-da-libp2p-transport.ts#L79), [scoped lifecycle and supervised start](../../../demo/midgard-node/src/fibers/foreign-da-reconciliation.ts#L64).

The tradeoff is deliberate: bounded fetching restores availability where payloads exist, while holding evidence preserves safety when they do not. Root reconstruction proves that the supplied body agrees with the retained commitments. It does not independently execute the foreign block, prove that its UTxO transition is correct, or implement foreign ledger advancement. Those E4/E1 gaps remain release constraints. Synchronous root reconstruction still consumes CPU within the existing whole-payload format; an asynchronous timeout does not preempt synchronous JavaScript. The A6 structural redesign remains relevant. Peer selection currently uses the first configured address of each committee member, and the watcher parser's existing peer cap applies. Permanently lost payloads therefore still require an authoritative recovery/finality path; retry cooldown is not that proof.

The larger packet checks must retain those limits rather than promote these focused tests into an acceptance claim.
