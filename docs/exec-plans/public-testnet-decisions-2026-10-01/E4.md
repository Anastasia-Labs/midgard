# E4 — Fault-proof program issue

Created [Midgard issue #695](https://github.com/Anastasia-Labs/midgard/issues/695), titled “[Fault-proof program] Fully verify foreign header commitments before building descendants”, labeled bug and needs-triage, with links to fault-proof program #501 and existing operator-attribution defect #683.

The original memo grouped two defects together. Their remedies are separate:

- **On-chain slashing attribution, #683:** enforce that each slashed operator is the operator of the block being removed. Update the pruning transaction builder to name that operator, and test valid removal across operator changes plus refusal of an unrelated operator. This is the E4 security priority. Off-chain replay cannot make an invalid slashing transaction impossible; an attacker can submit directly to Cardano.
- **Foreign-block verification, #695:** the current foreign-base path checks only the UTxO root without fully verifying the other commitments and counts. Repair this in E1's shared block execution/import path. It lets honest operators safely build on peer blocks under the existing descendant-culpability rule. It neither closes #683 nor calls for a separate E4 verification framework.

Issue #695 distinguishes direct-root fast paths from complete replay and requests focused reproduction and positive/negative verification gates. Its scope clarification explicitly separates validator enforcement from honest-node verification.

Evidence is source inspection at `3027be19cb3bc740f83af0e155e34ab38c7cf894`, not an executed exploit. The relevant implementation is in commit-block-header.select-authenticated-foreign-base-candidate.ts, resolve-commit-base-ledger-entries.ts and the Aiken state-queue link-removal arm. No validator change is claimed by filing the issue. <!-- doc-links:historical -->
