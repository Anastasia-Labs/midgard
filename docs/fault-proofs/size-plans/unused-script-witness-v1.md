# `unusedScriptWitness` V1 state and fit plan

Category `0000002f` proves that one canonical field-6 inline script witness is
not selected by any authenticated script purpose. It remains a narrow family:
no missing-source, redeemer, script-decoding, or execution-validity predicate
enters an applied validator.

## State and transitions

1. `step_01` binds accepted/forced source, direction, exact
   `UnusedScriptWitness { script_index }` reason when forced, transaction
   identity, validation-trace root/count, and the field-6 coordinate.
2. `step_02` authenticates the exact producer-committed ScriptSources control
   and opens the named field-6 inline-source leaf. Wrongful acceptance binds
   the stage-11 audit state at the offending coordinate; wrongful rejection
   binds the complete stage-12 audit. The work-root-bound 31-field control is
   decoded on-chain and binds language, hash, encoded length, item commitment,
   and the complete source and purpose frontiers (count and peaks). A
   fabricated committed frontier is convicted through header trace invalidity
   rather than trusted as canonical.
3. `step_03` freezes the authenticated frontiers. Its domain-separated
   checkpoint binds transaction, witness coordinate/hash, cursor zero, total
   purpose count, and the next script.
4. `step_04` resumably authenticates every earlier inline source descriptor in
   canonical order, at most `maximum_scan_batch` (24) openings per
   transaction, staying on its own script until the alternate cursor reaches
   the accused coordinate. Any equal hash proves the named witness is shadowed
   (and therefore unused); a changed alternate-source descriptor, membership,
   or order is refused, and a batch shorter than its declared budget cannot
   idle the thread. The self-loop is required for soundness: consensus admits
   field-6 preimages up to 32,768 bytes, so an accused coordinate can sit
   behind hundreds of earlier inline scripts and one transaction can open at
   most a few dozen of them.
5. `step_05` resumably authenticates purpose leaves in canonical order under
   the same 24-item budget. The cursor advances only on the committed next
   leaf. A target-hash match records `used`; exhausting the exact committed
   count records `unused`. The self-loop preserves the domain-separated
   checkpoint and its own applied script.
6. `step_06` applies accepted/forced polarity, burns the computation-thread
   token, and permanently mints the proof token. Generic leased state-queue
   removal follows the existing canonical removal path.

## Semantic engine and maximum evidence

The family imports the frozen validation-trace, validation-Merkle, and
`script_proof_v1` engines. Every control is bound through header trace root,
event/source/direction/verdict/transaction identity, machine state, work root,
stage, and coordinate. A malicious producer cannot escape accountability by
fabricating the frontier: doing so changes the committed work root and opens
the trace-invalid arm. Maximum evidence is the purpose frontier and
script-source frontier, with one membership proof per submitted scan item.
Both scans are bounded per transaction and must resume until
`alternate_cursor == script_index` and `purpose_cursor == purpose_count`; an
empty or partial scan cannot finalize absence. Spend, mint, observe, and
receive purpose kinds are exercised. Inline and reference source descriptors
are exercised as alternatives; only an inline field-6 coordinate may be the
accused witness.

Off-chain, the canonical detection reads the machine's own retained
stage-11/12 discovery bitmap (`used_inline_bitmap`): an accepted transaction
is accused at the first inline coordinate whose retained audit state has its
bit clear, and a forced `UnusedScriptWitness` rejection is contradicted only
when the retained stage-12 terminal exists and the named bit is set. Native
execution descriptors are not consulted, because PlutusV3 executions never
emit them.

## Fit test

Apply all six validators backwards from the freshly built testnet blueprint.
Publish each complete reference script with the shared Van Rossem parameters,
then measure init, all steps including the maximum scan/resume branches,
cancel from every nonterminal step, permanent proof mint, and leased canonical
removal. The machine-readable ledger must retain positive margins against
15,872 publication bytes and the Cardano hard byte/memory/CPU limits. No
positive route may use oversized transactions, raised limits, or disabled
local evaluation.

## Emulator scenario tests

`tests/unused-script-witness-lifecycle.test.ts` runs, from generic
computation-thread `Init` through the six applied reference scripts:

1. wrongful acceptance at the maximum shape through the production actuator to
   the permanent mint and the state-queue removal;
2. wrongful forced rejection at the maximum shape to mint and removal;
3. honest accepted block (accused witness used, accused coordinate before the
   end of field 6) refused on chain at step 06;
4. honest forced rejection refused on chain at step 02: the machine's
   stage-11 stop never yields the stage-12 terminal the forced direction
   demands;
5. coordinate mutation on both sides (bound index ≠ audited index; forced
   reason coordinate ≠ leaf coordinate);
6. every authentication seam substituted once and refused by the validator
   (forced leaf reason/header/root/direction; validation-traces root,
   descriptor, event key, machine state, trace proof, retained control, source
   item/language/length/commitment/membership/frontier, wrong successor;
   alternate-source item/membership/order, short batch, over-budget batch;
   purpose item/kind/membership/order, checkpoint, short batch, over-budget
   batch);
7. cancel from every physical step (01 to 06);
8. interruption and resume after a real checkpoint of both self-loops: the
   on-chain datum is reproduced from the authenticated witness off-chain and a
   fresh actuator resumes from it;
9. permanent proof-token mint followed by removal in both directions;
10. the maximum shape above;
11. the adjacent coordinate (`script_index == source_count`) refused on chain,
    and `item_budget == maximum_scan_batch + 1` refused at both self-loops.

The suite ends with `assertCompleteLifecycleCoverage`.
`tests/unused-script-witness-publication-fit.test.ts` publishes the six
applied scripts under the 15,872-byte reserve;
`tests/unused-script-witness-fit-ledger.test.ts` pins the ledger.

## Risks

- `step_01` keeps an 894-byte publication reserve, the thinnest in the family;
  a library-level growth of the shared native-tx carriage would need a prune
  before regeneration.
- The forced direction can only contradict a `UnusedScriptWitness` claim whose
  transaction reached the stage-12 terminal. A forced rejection naming a used
  coordinate while a later coordinate really is unused commits the same
  rejection code with the wrong coordinate; that mismatch is outside this
  family and belongs to the trace-invalid arm.
