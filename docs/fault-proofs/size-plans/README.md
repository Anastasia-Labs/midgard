# L1 size-fit plans

One plan per compiled script that cannot be published as a reference script
under the 16,384-byte transaction limit. Read [`00-primer.md`](00-primer.md)
first; every plan assumes it.

Sizes are raw unapplied blueprint bodies from the reproducible 2026-09-01
build. `fraud_proofs/withdrawal_mistag/step_03` (25,518) is being fixed
separately and has no plan here.

## Landing order

All plans change applied-parameter hashes that ripple to the family first
step and the catalogue root, so they should be integrated as one blueprint
regeneration with a single catalogue-root re-pin. The dependency-ordered
sequence (library changes → yields → RF-021 chain extension and the CEK
chains → one prepare/first-step/catalogue re-application → off-chain roles,
routes and fixtures → dropping `oversized: true` per group) is in the
primer's "Landing order" section; each plan's §10 names its own
prerequisites.

Ownership of shared designs, as reconciled on 2026-09-02:

- Redeemer-item-step decomposition in `mode_data`: the stage-one-redeemer
  plan (RF-021 chain executors, plus a second carrier for CEK context stages
  0/9). The stage-ten-match plan owns only the `mode_descriptor` surface and
  `V1VtSsRedeemerItemStepYield`.
- Semantic-yield handshake `require_semantic_yield_v1`: the non-output plan.
- Ledger-output-proof stage and descriptor yields (`V1VtLop…`): the
  output-proof-step and output-proof-finalize plans; resolve-inputs
  membership step/finalize reuse them.
- Value-and-mint asset-fold yield: the replay-asset plan.
- Phase-A PA-CARRY / PA-UNDECODED: the signature-between-payload plan.
- Transition-trace `output_summaries` yield: the accepted-transaction plan.
- Role names follow the primer's "Naming" section (all ≤ 32 bytes).
